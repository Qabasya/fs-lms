# Экзамены вне курса (public exam): правила кода

Загружается при работе с `inc/Services/Exam/`. Общие правила — в корневом `CLAUDE.md`, спецификация —
`.docs/public-exam-feature/` (`SPEC.md`, `tasks/README.md` — контракт имён, `tasks/stage-NN.md` — задачи).
Ниже — то, что **исправлено рефакторингом 2026-10-04** и теперь обязательно; каждый пункт закреплён тестом.

## Данные и транзакции

- **Ошибка базы — исключение, а не «пусто».** Репозитории экзаменов наследуют `AbstractExamRepository` и читают/пишут только его
  хелперами: `readRow()`, `readRows()`, `readInts()`, `readInt()`, `insertRow()`, `updateRow()`, `write()`. Прямой
  `$wpdb->get_row()` с `$row ? DTO : null` превращает сбой запроса в «строки нет». Разбор `errno`: 1213/1205 → `RetryableDbException`,
  1062 → `DuplicateKeyException`, остальное → `\RuntimeException`. Метод `update()`, возвращающий `false`, который никто не
  проверяет, не заводить: нужен метод с проверкой числа затронутых строк.
- **Границы транзакции проверяются** (`TransactionRunner`): провал `START TRANSACTION` или `COMMIT` — исключение. Повтор при
  deadlock — только `inTransactionWithRetry()`, тело транзакции должно быть безопасно для повтора.
- **Первый оператор транзакции — блокирующее чтение (`FOR UPDATE`)**, а всё, что нужно для выбора блокируемой строки, читается ДО
  `START TRANSACTION`. Под REPEATABLE READ снимок данных создаёт первое же *обычное* чтение транзакции; прочитанное до блокировки
  не увидит записей, зафиксированных другой транзакцией за время ожидания. Так на реальной базе два одновременных запроса одного
  участника занимали два пересекающихся сеанса, а «перечитывание под блокировкой» возвращало устаревшую попытку.
- **Порядок блокировок един:** участник (только там, где проверяется пересечение между проведениями) → участие → сеансы по
  возрастанию ID. Строка участника — единственная общая точка сериализации одного человека между проведениями.
- **Состояние под блокировкой.** Сохранение ответа, сдача, автоистечение, старт, неявка и отмена блокируют одну и ту же строку
  участия и проверяют статус и дедлайн уже под ней. Проверка «до» блокировки — только для раннего отказа и ленивого завершения
  (оно идёт в своей транзакции, поэтому вызывается вне чужой).
- **Версия участия** (`exam_participations.version`) растёт при любом изменении указателя (`setActiveRegistration`, `setCurrentAttempt`).
  Операции ученика с записью (`change`, `cancelBySelf`) принимают `expectedVersion` из карточки и отвечают `ExamStale` при расхождении;
  повтор по `request_key` версию не проверяет (он возвращает прежний результат).
- **Порядок блокировок для проведений и кабинетов:** проведение → кабинет → сеанс. Сеанс в кабинет назначают `ExamEventService::saveSession()` и
  `RoomAssignmentService` (занятия): оба берут блокировку строки кабинета (`ExamRoomService::lock()` / `RoomRepository::lockForUpdate()`) до проверки «свободен ли кабинет» и пишут в той же транзакции —
  без этого два назначения в один кабинет на одно время проходят вместе (проверено стендом `room-race`). Единственная точка «свободен ли
  кабинет» — `RoomAvailabilityService` (занятия и сеансы экзаменов); прямой `RoomRepository::isBusy()` в новом коде не звать.
- **`confirmHeld()`/`confirmLate()` своей транзакции не открывают:** их зовёт `ExamHoldService::convert()` под своей блокировкой заявки. Освобождение места
  брони — условный `UPDATE ... is_held` (`releaseHeldFlag`): место возвращается ровно один раз, сколько бы тиков и оплат ни пришло одновременно.
- **Одно правило — один метод.** Пересечение по времени — `assertNoOverlap()` и для записи, и для переноса; допустимые предметы
  ученика — `eligibleSubjects()`; сборка разбора — `assemble()`; сохранение/завершение попытки — `AttemptService::saveAnswerFor()` /
  `submitFor()` (старые `saveAnswer()`/`submit()` лишь проверяют владельца и зовут их).

## Время

- `exam_*` — UTC, `assessment_attempts` и занятия — местное время сайта. Переводит только `ExamTime`.
- **`NOW()` базы с местным временем не сравнивать:** пояс сервера БД может расходиться с поясом сайта (на dev — на 3 часа).
  «Сейчас» всегда параметром из `ClockInterface::now()` / `ExamTime` (так сделаны `findAnyActive()`, `findPending()`).

## Попытка и раскрытие результата

- **Официальную попытку ведёт только `ExamAttemptService`.** Старый путь (`AttemptService::saveAnswer()/submit()`) экзаменную
  попытку отвергает; `AttemptCallbacks` выбирает путь по самой попытке (`contextForAttempt()`), а не по параметру запроса.
- **Один вопрос «можно ли показать итог» — один ответ:** `AttemptService::isRevealed()`. Им пользуются результат, ответ на сдачу,
  страница станции, разбор. До утверждения ни в одном ответе (JSON, HTML) нет баллов, вердиктов, эталонов и решений.
- Ошибки сервисов с кодом — `CodedException` → `fail()`; клиент берёт текст через `ajaxErrorText()` (`common/utils.js`): ответ
  `fail()` — объект `{message, code, ref}`, а не строка.

## Клиент и ответы

- Ответ операции записи (`LearnerExamCallbacks::run()`) — список карточек **и** `warnings` операции (`lesson_overlap`: сеанс пришёлся на занятие, запись при этом
  создана). Предупреждение, которое сервис формирует, обязано дойти до клиента: проверять тестом на ответ коллбека, а не только на результат сервиса.
- Блок с атрибутом `hidden` обязан реально скрываться: базовые классы (`.sc-notice { display: flex }`) его перебивают — нужен `...[hidden] { display: none }`
  (так был виден пустой синий блок под карточкой экзамена). Проверять в браузере по `offsetHeight`, а не по атрибуту.
- Вид работы «станция» (ЕГЭ/ОГЭ) нельзя назначить работе, которая уже стоит шагом урока (`AssessmentKindGuard`): станция живёт вне курса.

## Тесты

- Юнит-тесты на моках проверяют логику и **порядок вызовов** (блокировка до чтений, перечитывание после неё), но гонок не доказывают.
  Гонки, блокировки и поведение снимка — на настоящей MariaDB: параллельные процессы (`xargs -P`) против одной строки, затем
  проверка инвариантов (`occupied_count` = числу действующих записей; у участника нет пересекающихся записей).
- **Не править `inc/` во время прогона стенда или браузерного e2e.** Правка посреди прогона (недописанный трейт, переименованный класс) роняет сайт, и
  прогон проверяет уже не то, что задумано. Правки — атомарно (файл целиком, `php -l`), до или после прогона.
- Стенд `start-vs-missed` (граница «старт или неявка»): все процессы заранее грузят WordPress и ждут общего момента (`--at`); запас до границы сценарий
  измеряет сам (время загрузки такого же числа процессов × 2 + 45 с), иначе проверяется не гонка, а опоздание. Ожидание: у каждого участника ровно один исход —
  попытка или неявка, обоих сразу нет.
- Мутационная проверка ключевого теста: временно убрать защиту в коде — тест обязан упасть.
- Dev-стенд: адреса экзаменов (`/{key}_assessments/ID/`) дают 404, пока не сброшены правила переадресации
  (`flush_rewrite_rules()`); `docker restart wp_app` — после правок PHP, если поведение не меняется (OPcache).

## Проведение, утверждение, исправление (этап 8)

- **Один вопрос «можно ли сотруднику работать с экзаменной попыткой» — один ответ:** `ExamConductService::canManageAttempt()` (проведение попытки + `ExamAccessGuard::canManageEvent()`). Им пользуются
  `GradeAttemptCallbacks` и `GradingCallbacks`; попытка без группы и без экзаменного контекста отклоняется, а не пропускается.
- **Версия результата (`result_version`)** растёт при каждой записи оценки экзаменной попытки (`bumpResultVersion()` — условный `UPDATE`, ровно одна строка) и при исправлении; утверждение версию сверяет, но не меняет.
  Клиент обязан передавать версию, которую видел (`work-review.js: versionParams()`), устаревшая — `X-STALE`.
- **Утверждение и исправление идут под блокировкой участия** (`ExamApprovalService`): состояние попытки читается после неё. Массовое — по транзакции на работу. Проверено на MariaDB (`NOTES.md`, этап 8).
- **Отмена сеанса/проведения сначала закрывает сеанс/проведение, потом отменяет записи** по одной (`ExamRegistrationService::cancelByStaff()` открывает свою транзакцию — вложить её нельзя). Повторный вызов доводит оставшиеся.
- **Завершение проведения** — только `ExamEventService::completeIfDone()` из минутного тика, после неявок и автоистечения.
- **Исправление никогда не меняет `answer_text`**; критерии (`criteria_scores`) описывали прежний балл и сбрасываются.
- **Выгрузка и печать списка участников** — только при `ManageLmsPlatform` + `ExportPII` и доступе к проведению; контактов нет ни в CSV, ни в списке печати. Защита от формул — `CsvExportService::neutralizeFormula()` для всех выгрузок.
- Стенд: `stand-attempts`, `stand-approve`, `stand-approve-all`, `stand-correct` (`ExamStandCommand`) — для гонок утверждения и исправления.

- Доску и строки CSV/печати собирает `ExamConductViewService`, список результатов — `ExamResultsViewService`. AJAX и провайдер экспорта получают их напрямую; командный Conduct ради чтения доски/имени не подключать.
- Общее состояние работы вычисляет `ExamResultStatusService` с enum `ExamResultStatus`; вывод имени — `ExamParticipantNameService`; варианты фильтров проведения — `ExamEventViewService`. Значения ответов клиенту сохраняются.
- Общий разбор без контактов собирает `ExamReviewViewService`; контакты центра добавляет только `GuestResultViewService`. Для проверки допуска использовать дешёвый `ExamReviewProjection::isParticipationRevealed()`, не собирать review и не кешировать раскрытие между запросами.

## Уведомления (этап 9)

- **Только кабинет.** Писем, SMS, мессенджеров нет; **гостю LMS не отправляет ничего** (`ExamNotificationComposer::studentRecipients()` для аудитории `guest` пуст).
- **Событие → уведомление только через outbox.** Сервис пишет `ExamOutbox::add()` в своей транзакции, `ExamOutboxWorker` после фиксации отдаёт строку композитору. Прямой `NotificationService::push()` из сервисов экзаменов не звать.
- **Ключ дедупликации строится из события** (`exam:{тег}:{агрегат}:{версия}`), поэтому повтор обработки не вставляет дубль; исключения (утверждение, исправление, продление, лимит заявок) описаны в докблоке композитора. Новое событие — новый ключ и тест на стабильность.
- **Сбой доставки не влияет на допуск:** старт проверяется сервером в момент запроса. Строка с 10 неудачами остаётся в outbox с `last_error`.
- **Напоминания** (`ExamReminderService`): перед отправкой запись перепроверяется; отмена, перенос, неявка снимают плитки (`retractReminders()`).
- Порядок тиков и состав шагов — в докблоке `ExamTickService`; cron на сервере — `.docs/public-exam-feature/HANDOFF.md`.

## Статистика (этап 10)

- **Единица подсчёта — участие**, а не строка записи (`ExamStatsService`): перенос не даёт «+1 записано», отменённая запись без попытки не считается.
- **Шкалы не смешиваются:** средние — по направлению первой оценённой работы, остальные дают `format.mixed`; у каждого среднего есть `sample`.
- Разбор по заданиям строится из строк ответов (вердикт по правилу 7.2.1), а не через `WorkDetailService` — тот собирает условия и для массовой выборки слишком дорог.
- Новый показатель — тест на фикстуре с ручным подсчётом.

## Гость, ссылки и отчёты (этапы 11–12)

- **Гость не пользователь WordPress.** Личность — сессия (`exam_guest_sessions`, в базе хеш куки). Сессия входа (`entry`) — единственная, что даёт контекст попытки (`GuestSessionService::current()`); результат (`result`) и отчёт (`report`) — только просмотр своей страницы. Проверка сессии, поколения ключа и (для отчёта) срока — **на каждом запросе**.
- **Параметры адреса страниц гостя:** идентификаторов попытки и участия не читаем; у отчёта строка — порядковый номер `?row=` (не `p`: WordPress занимает `p` под ID записи и покажет чужую страницу).
- **Отчёт — только состав, баллы не хранит:** итог читается из попытки при каждом построении; допуск строки (`ExamReportService::canInclude()`) перепроверяется каждый раз — отозванное согласие или снятое утверждение превращает строку в заглушку.
- **AJAX-параметры кабинета:** `profile/api.js` кодирует массивы как `key[]`, объекты — `key[i][поле]`; свой `URLSearchParams` из объекта массив склеит в «1,2» (так не работали выбранные выгрузки и массовое утверждение).
- **Тесты:** `user_can()` в юнит-тестах управляется `$GLOBALS['_test_user_can'][id][cap]`, `current_user_can()` — `_fs_test_can_callback`.
- Страницы гостя и отчёта: HTTP/шорткоды — ExamGuestPageController, политика — GuestPageAccessService, заголовки только через `GuestPageResponder`; нет сессии — обычная 404 темы. Определения четырёх страниц — PageRoutes::guestExamPages()/guestExamTitle()/guestExamShortCode(). Общий генератор проверяет публикацию через PostManager; версия миграции записывается только после успеха всех страниц.
- Все четыре защищённые страницы (`signup`, `entry`, `result`, `report`) перепроверяют доступ при восстановлении из bfcache: подписка на `pageshow` не зависит от AJAX-конфигурации. Robots задаёт штатный фильтр `wp_robots`, canonical на этих маршрутах отсутствует.
- Поле серверной ошибки согласия совпадает с `data-error` формы (`consent_pd_processing`). Неизвестный ключ ошибки обязан показывать общий текст; заполненные данные и request_key сохраняются при повторе.
- **Ссылки приглашения, школьного отчёта и входа гостя хранятся зашифрованными** (`exam_access_tokens.key_enc`, `ExamAccessTokenService::invitationKey()/reportKey()/entryKey()`): сотрудник копирует действующую ссылку, не перевыпуская её (строка доски — «Скопировать ссылку», поле `entry_link_url`). Ключи результата и оплаты не хранятся. Ссылка, выпущенная до хранения, копируется только после повторной выдачи.
- **Скидка по ссылке преподавателя** — `exam_sources.discount_percent` (0/25/50/75/100, `ExamSourceDTO::DISCOUNT_STEPS`; `Migration_1_0_88` заменила `is_free`, колонка `is_free` осталась, но не читается; у открытой записи скидки нет — `effectiveDiscount()`). 100 % (`isFree()`): бронь сразу превращается в запись через `ExamHoldService::convert( $id, null )`, магазин не вызывается; не подтвердилось — бронь снимается и клиент берёт новый `request_key`. 1–99 %: процент фиксируется в `source_snapshot.discount_percent`, цену экзаменной позиции корзины пересчитывает `woocommerce_before_calculate_totals` (`WooExamAdapter::discountedCartPrices()`, заявка берётся только по верной подписи); форма гостя считает цену той же формулой (`GuestSignupViewService::price()`) и показывает плашку «скидка по ссылке преподавателя».
- **Сеансы ссылки школы** — `exam_sources.session_ids` (JSON-список ID, `NULL` = все сеансы; `Migration_1_0_92`, `ExamSourceDTO::allowsSession()`). Ограничение действует и на показ (`GuestSignupViewService::sessionCards()`), и на запись (`GuestApplicationService::apply()` — проверка по источнику, а не по форме); новый путь записи гостя обязан звать `allowsSession()`. Ручная заявка сотрудника ограничение обходит. Число записанных по ссылке (`payload['registered']`) — участия с действующей записью; удаление источника отказывает при действующих заявках/записях/отчётах и само гасит ссылку и гостевые сессии.
- **Сеанс только для гостей** — `exam_sessions.visible_to_students` (`Migration_1_0_93`, `ExamSessionDTO::$visibleToStudents`, по умолчанию 1). Выключенный сеанс не виден ученику и родителю (`LearnerExamsService::futureSessions()`, кроме их текущей записи) и недоступен для самозаписи (`ExamRegistrationService::register()/change()` → `assertVisibleToStudents()`); гости и сотрудник (запись, перенос) его видят. Скрыть можно, только пока в проведении включена запись гостей (`saveSession()`), и выключить гостей при скрытых сеансах нельзя (`updateEvent()`). Новый путь самозаписи ученика обязан звать `assertVisibleToStudents()`.
- **Сохранение сеанса, когда меняется только показ** — если вариант, начало и кабинет те же и пришёл `visible_to_students`, `saveSession()` пишет только поля показа: не пересчитывает конец и вместимость и не проверяет кабинет, занятость и «сеанс начат» (иначе начатый или прошедший сеанс нельзя скрыть, а смена длительности формата выглядела бы переносом). Любое изменение времени, варианта или кабинета идёт прежним путём со всеми проверками.
- **Неявка гостя переносится сотрудником** (`ExamRegistrationService::transferByStaff()`, пункт «Назначить другой сеанс»): неявка уже закрыла запись и вернула место, поэтому перенос не закрывает старую запись и не освобождает место, а только занимает место в новом сеансе и создаёт действующую запись (в outbox и журнале — `from_missed`). Только гость и только когда у участия нет действующей записи; у ученика своя запись. Новый путь «вернуть из неявки» идёт этим же методом, а не отдельным.
- **«Запись подтверждена» — ручная отметка сотрудника, а не статус записи и не допуск:** `exam_participations.staff_confirmed_at` / `staff_confirmed_by_user_id` (`Migration_1_0_100`, `ExamConductService::confirmGuest()`, действие `confirm_guest`). Ставится при действующей записи гостя, снимается всегда; на ссылку входа, допуск (`admitted_at`) и попытку не влияет. На доске — зелёный бейдж «Подтверждено» в `exam-guest-pills` (у отменённой записи не показывается). Не путать со статусом `ExamRegistrationStatus::Confirmed` — это «запись действует».
- **Школа гостя:** у ссылки школы она берётся из источника, из формы не читается; в открытой записи гость может назвать её сам (`school`, необязательно, ≤255) — попадает в снимок участника, ключа справочника у неё нет. Школу участника отдаёт только `ExamParticipantProfileService::school()`.
- **Фильтры результатов:** группа действует на наших учеников, источник — на гостей, школа — на всех; заданы группа и источник вместе — показываются оба набора. Скрытый для выбранной аудитории фильтр клиент сбрасывает.
- Ручная заявка сотрудника сохраняет реальный RequestContextProvider (IP, User-Agent, actor); исключение сотрудника из IP-лимитов определяется отдельно через staffUserId. Технический сбой платёжного перехода журналируется без секретного ключа.

### PHPDoc и проверки типов после рефакторинга

Типы простых параметров задаются в сигнатуре; PHPDoc уточняет array shapes, списки и callable там, где это помогает контракту. Не дублировать все DI-параметры ради заполнения докблока. Проверку имён/совместимости уточнённых типов выполняет PHPStan уровня 5. Squiz сравнивает неполные @param по позиции и не понимает современные shapes/callable: соответствующие четыре требования согласованы в phpcs.xml. Документация объясняет назначение и ограничения, а не пересказывает имя метода. Экранирование HTML остаётся обязательным на границе вывода. ExceptionNotEscaped исключён только для inc/Services/Exam: сервисы передают типизированный ErrorCode и обычный текст в JSON/журнал, не выводят аргументы исключения как HTML. Сам sniff EscapeOutput для фактического вывода не отключён; клиентские ошибки записываются через textContent/text() или экранируются при сборке HTML.

Исключения из замыкания TransactionRunner доходят до вызывающего метода и входят в его @throws-контракт. Squiz считает только прямые throw и неверно требует убрать тип такого отказа: WrongNumber согласован в профиле, сами @throws с причинами сохраняются. Компактные PHPDoc с несколькими тегами разворачивать в многострочные блоки. Для WP/Woo-хуков PHPDoc не должен сужать mixed до всегда существующего объекта: проверки входа остаются обязательными.


**Коды отказа.** `ExamConflict` (`X-CONFLICT`, «пересечение с другим») — только настоящее пересечение или дубль (кабинет занят, запись на другой экзамен в то же время, повторная запись). «Не найдено» — `ExamNotFound`, недопустимое состояние — `ExamState`, ошибка ввода — `ExamInput`. Универсальным «отказом» `ExamConflict` не пользоваться: журнал «Ошибки» показывает подпись кода, и неверный код вводит в заблуждение (так удаление сеанса с записями выглядело как «пересечение»).

**Журнал «Экзамены».** Одна таблица `exam_log` и один канал `LogChannel::Exams` на все действия (проведения, сеансы, записи, гостевые заявки, допуск, попытки, проверка, ссылки, отчёты, оплаты, форма записи). Действие — кейс `ExamLogAction`; сервис сообщает о нём одной строкой `ExamLogAction::X->record( array( 'event_id' => …, 'actor' => $actorUserId, 'context' => … ) )` (хук `fs_lms_exam_logged` → `ExamLogController` → `ExamLogWriter`). Правила:
- вызывать **после успешной операции** (после коммита, а не в середине блокировок); писатель сам гасит сбой записи, действие журнал не ломает;
- передавать только то, что известно: `registration_id` / `attempt_id` / `participation_id` писатель достраивает до проведения, сеанса и участника и подставляет ФИО (нет ФИО — номер). Актор не назван — это пользователь текущего запроса; крон, тик и магазин передают `actor_type => system`, гость — `actor_type => guest`;
- в `context` — причина, было/стало, коды; **не** телефон, email, ключи и токены ссылок. ФИО участника допустимо (согласия есть), вне колонки `subject_label` его не дублировать;
- срок хранения журнала — как у данных гостей (`examGuestRetentionDays()`, `RetentionService::purgeOldExamLogs()`);
- новое действие — кейс в `ExamLogAction` (значение не менять: по нему фильтруются старые записи) и тест у вызывающего сервиса; ошибки по-прежнему идут и в «Ошибки» (`ErrorCode`), в «Экзамены» пишется бизнес-контекст.
- **Исключение из правила nonce:** `AjaxHook::LogExamClientEvent` (технические события станции из браузера: закрыта вкладка, потеряна сессия, не сохранился ответ) работает без nonce — он нужен как раз тогда, когда сессия и nonce уже недействительны. Защита: белый список видов, лимит `RateLimitService::allowExamClientEvent()`, проверка идущей экзаменной попытки; ответ всегда `success`.

- **Время ответа на задание** — `assessment_answers.first_answered_at` / `answered_at` ведёт `AssessmentAnswerRepository::saveAnswer()` одним запросом (первое непустое значение; `answered_at` двигается только при реальной смене текста и не раньше чем через `AssessmentAnswerRepository::ANSWER_MERGE_SEC` (30 с) после прошлой отметки — правка сразу после ответа не даёт второго времени; пустой ответ время не трогает; клиент шлёт автосохранение после паузы 7 с, а не на каждый ввод). Ученический ответ пишется только через него, не через `upsert()`. Смещение от начала считает `WorkDetailService::offsetSec()` (`answer_first_sec`/`answer_last_sec`), в текст «ЧЧ:ММ:СС» его переводит `ExamReviewViewService`. У обычных работ те же ключи берутся из `task_attempts.first_answer_sec/last_answer_sec` (замер плеера, по раундам).
