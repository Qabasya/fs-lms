# Режим обслуживания: предварительный инвентарь

Дата: 2026-11-07. Статус: **инвентаризация не завершена**. Этот документ фиксирует проверенные точки и оставшиеся проверки; он не является списком разрешённых операций.

## Транспорты и политика

| Точка | Класс операции | Необходимое поведение |
|---|---|---|
| `Controllers/System/AjaxController::registerAjaxHooks()` и наследники | Чтение и пользовательская/административная запись | Проверка каждого зарегистрированного `AjaxHook`; неизвестное действие не разрешать как чтение. Проверить каждый callback и его транзитивные вызовы перед включением в allowlist. |
| Прямые AJAX-регистрации `AllTasksPageController`, `ProblemsController`, `ModulesDashboardController` и модулей | Смешанные | Не проходят через `AjaxController`; нужны отдельные подключения политики. Модульные экшены определяются внутри модулей. |
| `VideoRestController::postVideo()` POST `/fs-lms/v1/videos` | Внешняя автоматическая запись; `dry_run` — предварительный просмотр | После HMAC возвращать временный 503 без записи. Сохранить текущий формат `{ok:false,error:...}`, дополнить кодом `maintenance_active` согласно согласованному контракту. |
| `ContentDeletionGuard` `admin_action_*` | Ручная административная запись | Сохранить существующие права; проверить покрытие политикой для остальных ролей. |
| `WooExamController`: корзина, checkout, удаление позиции | Пользовательская запись | Блокировать новые операции с экзаменационными товарами, включая классический checkout и Store API; фактическое покрытие хуками Store API требуется проверить. |
| `WooExamController::onOrderChanged()` | Внешнее подтверждение оплаты | Не терять подтверждение уже оплаченного заказа: отложить и обеспечить повторную идемпотентную сверку `ExamPaymentReconciler`. Простой отказ webhook без проверки поведения платёжного провайдера недостаточен. |
| WP-CLI `inc/Cli/`, `Modules/AdSync/Cli/` | Ручные серверные операции | Разрешать явный запуск; автоматическую почту и доставку интеграций не включать неявно. Отличать системный cron, вызывающий WP-CLI, от ручного контекста. |
| `AdSyncController::flushAfterResponse()` | Автоматическая доставка после ответа (`shutdown`, приоритет 100) | Проверять политику до доставки и каждого пакета, сохранять очередь; cron-guard недостаточен. `ErrorLogController` также использует shutdown, но это аудит, разрешённый планом. |
| Выход из WordPress | Безопасное завершение сессии | Оставить доступным; альтернативные пути входа и авторизации требуют отдельной проверки. |

Контракт отказа: HTTP 503, код `maintenance_active`, понятный текст «Сейчас ведётся техническое обслуживание. Попробуйте позже.»; форма ответа соответствует транспорту (AJAX/REST). Проверенные безопасные чтения возвращают обычный ответ. Не определять безопасность по имени действия, HTTP-методу или `is_admin()`.

## Чтение с побочными записями

| Место | Наблюдение и действие |
|---|---|
| `PresenceController::register()` → `PresenceService::touchCurrentUser()` на `init` | Обновление присутствия происходит независимо от конкретного экрана; при обслуживании нужно отдельно остановить запись. |
| `ExamAttemptService::result()` и `stationState()` | Вызывают `finalizeExpired()`, который меняет попытку; нельзя разрешать эти чтения без отделения вычисления состояния от записи. `activeAttemptOf()` тоже вызывает `finalizeExpired()`. |
| `LearnerExamsService` | `build()` вызывает `ExamNoShowService::markMissed()` при построении карточек. В том числе `GetLearnerProfile` вызывает этот путь через `LearnerService::highlightsFor()` для пилотных логинов (по умолчанию `belova2024`); `upcomingEvents()` отдельно эту запись не вызывает. Отложить запись, сохранив корректное вычисляемое представление и права доступа. |
| `LessonPlayerCallbacks` → `LessonProgressService::markViewed()` / `markCompleted()` | Это явная запись прогресса, не считать просмотром только потому, что пользователь открыл материал. |
| `NotificationCallbacks` → `markRead()` | Явная запись прочитанности; блокировать, отображение уведомлений сохранить. |
| `WooExamController::checkCart()` → `WooExamAdapter::cleanCart()` | При проверке корзины удаляются устаревшие позиции; также `onItemRemoved()` снимает бронь. Проверить обе цепочки и отложить доменные изменения. |

Не завершены трассировка первого открытия ЛК и всех ленивых истечений брони/просмотров/видео; до проверки соответствующие пути не объявлять чистыми.

## Фоновые задачи и почта

`CronController` регистрирует истечение попыток, уведомления с автоотметкой посещаемости и административными сигналами, снимки рейтинга, экзаменационные auto-expire, освобождение броней и доставку outbox. `RecoveryController` регистрирует recovery, истечение заявок и retention cleanup. `AdSyncCronController` отдельно запускает delivery и reconcile. Останавливать выполнение, не удаляя расписание и очередь; проверить состояние непосредственно в сервисных точках и перед записью. Существующие блокировки экзаменационных тиков сами по себе не подтверждают остановку всех воркеров и не устраняют гонку при включении.

В `inc/` найден один прямой вызов `wp_mail()` — `EmailService::send()`. Его вызывают welcome/credentials, course granted и OTP; например `EnrollmentService`, `EnrolledStudentRowImporter`, `OpenGroupEnrollmentService`, `EmailOtpService`. Проверка только этого вызова не доказывает отсутствие писем WordPress/WooCommerce: происхождение писем WooCommerce, очереди и побочные события оформления заказа надо проверить отдельно. При подавлении отправки не маркировать письмо доставленным и не терять задачи на повтор без согласованного решения.

## Внешние процессы

`VideoRestController` подтверждает HMAC и существующий временный 503; комментарий указывает, что 4xx для uploader терминален. Документация `.docs/FS_LMS_API.md` называет отдельный `fs-video-uploader`, загружающий видео в S3 до регистрации в WP. Его исходный код и реально работающий backoff в этом репозитории не подтверждены; отказ регистрации не останавливает скачивание или S3-загрузку. Требуются проверка кода/конфигурации демона и поддержанная серверная остановка или протокол подтверждённой паузы.

`.docs/AdSyncPythonService.md` описывает 503 при недоступном контроллере домена и паузу доставки от минуты до часа без расходования попытки. Это контракт интеграции, а не подтверждение остановки Python-процесса. Не показывать статус подтверждённой внешней паузы без подтверждения процесса.

## Подробный реестр AJAX и модулей

[Реестр core AJAX](MAINTENANCE-AJAX-INVENTORY.md) содержит 302 регистрации из контроллеров, включая квадратные массивы и два прямых хука. Часть действий размечена по вызовам обработчиков; оставшиеся и требующие проверки транзитивных вызовов не являются allowlist. Количество относится к найденным регистрациям, а не к гарантированно полному перечню всех способов вызова.

| Источник прямого AJAX | Действия / назначение | Дальнейшая проверка |
|---|---|---|
| `PublicExamsModule` | `PublicResultCallbacks::ACTION`, гостевой результат | Проверить побочные эффекты построения результата до разрешения. |
| `EgeComputerModule` | preview результата, ZIP файлов | Проверить доступ, побочные эффекты и запись временных файлов. |
| `SmartCaptchaSettingsController`, `DaDataSettingsController`, `ModulesDashboardController` | сохранение настройки/переключение модуля | Административные изменения; сохранить nonce и существующие права, применять политику к неадминистраторам. |
| `AdSyncSettingsController` | save, check, flush, retry, full sync | Save/retry/flush/sync меняют настройки, очередь или внешний AD; даже администратору автоматическая доставка при обслуживании запрещена. Check требует отдельной проверки побочных эффектов. |
| `AdAccountController`, `AdSyncController` | состояние/создание учётки, статус | Provision — внешняя запись; state/status проверить по обработчикам перед разрешением. |
| `VideoLibrarySettingsController` | save и экспорт groups | Save — настройка; экспорт проверить отдельно. |
| `VideoLibraryController` | lessons, attach, detach, pending, set URL, teacher attach, watch | Attach/detach/set URL — изменения; watch и списки проверить, в частности учёт просмотра и выдачу временного URL. |

WP-CLI содержит не только ручные изменения: `ExamCommand::tick` может выполнять те же автоматические операции, что cron, а `AdSyncCommand::flush` без `--respect-pause` принудительно обходит текущую сетевую паузу. Нельзя приравнивать `WP_CLI` к подтверждению ручного запуска. `VideoInventoryCommand`, переносы предметов, перерасчёты и исправления заданий требуют отдельной классификации по их методам.

Дополнительно: `NotificationCallbacks::ajaxGetNotifications()` при открытии списка вызывает `markAllSeen()`, поэтому это чтение с записью. `GetNotificationsCount` включает `PinnedNotificationService::forUser()`; проверенная цепочка читает уведомления, пользователя, лицо и связанные записи и вычисляет ответ без отметки seen. `EndExamGuestSession` отзывает гостевые токены и удаляет cookie после проверки сдачи; его возможное исключение как безопасного выхода необходимо решить отдельно. `LogLearnerActivity` и `TrackExamSignupForm` пишут журналы, причём второй также использует rate limit; их допустимость зависит от согласованной политики аудита.

`GuestApplicationCallbacks::ajaxCheckExamApplicationStatus()` вызывает `reconcileOrder()` при запросе статуса: пользовательский просмотр может изменить записи об оплате. Для режима обслуживания отделить отображение статуса от сверки и надёжно отложить подтверждение. `UploadAnswerFile` создаёт вложение даже для гостя; этот публичный экшен блокировать. Проверки доступности логина и email расходуют rate limit; события форм и технических ошибок пишут журналы.

Проверен исходный код установленного WooCommerce в соседнем каталоге `wp-content/plugins/woocommerce`: Store API `Utilities/CartController.php` вызывает `woocommerce_add_to_cart_validation` и `woocommerce_check_cart_items`. Однако `Routes/V1/Checkout.php` и `CheckoutOrder.php` вызывают `woocommerce_store_api_checkout_order_processed`, тогда как `WooExamController` подписан на `woocommerce_checkout_order_processed`. Это не доказывает, что классическая привязка заказа работает в Store API. Нужна отдельная интеграционная проверка оформления и блокировки на установленной версии, включая уже начатую оплату и сохранение подтверждений; поведение конкретного шлюза и его webhook кодом этого репозитория не подтверждено.

Поиск по дереву `/Users/daniil/FS-LMS` не обнаружил исходных файлов с именем `video-uploader`, daemon и Python-проектов; это не доказывает отсутствия отдельно развёрнутых процессов или проектов вне данного дерева. Проверить код, конфигурацию и состояние процессов можно только в среде их развёртывания.

## Дополнительная трассировка 2026-11-09

| Путь | Подтверждённый эффект и следствие |
|---|---|
| `VideoLibraryCallbacks::ajaxWatch()` → `VideoAccessLogService::logWatch()` → `VideoAccessLogRepository::touch()` | Heartbeat записывает накопленные секунды просмотра после проверки доступа. Это не чистое чтение; остановить запись на время обслуживания либо явно отнести её к разрешённому аудиту. |
| `RecordingUrlService` → `VideoAccessLogService::logPresign()` → `VideoAccessLogRepository::touch()` | Выдача временной S3-ссылки также записывает запрос в журнал доступа. Разрешение просмотра зависит от решения об аудите; права на видео и подпись ссылки сохраняются. |
| `HomeLayoutService::get()` → `UserManager::homeLayout()` | Этот конкретный путь нормализует прочитанную раскладку в памяти; `setHomeLayout()` вызывается отдельно в `save()`. Это не доказывает чистоту остальных секций первого открытия кабинета. |
| `PinnedNotificationService::forUser()` | Выбирает и фильтрует уведомления и вычисляет выполнение по данным репозиториев; проверенные методы репозиториев читают данные, `NotificationService::toClientArray()` форматирует ответ. Детали `GetNotificationsCount` приведены в AJAX-реестре. |
| `EmailOtpService::sendCode()` → `EmailService::sendOtpCode()` | Код и сброс счётчика сохраняются до отправки, возвращаемый результат отправки игнорируется и cooldown устанавливается после неё. Одного запрета `wp_mail()` недостаточно: он оставит недоставленный код и задержку повторной отправки; блокировать операцию до создания кода. |
| `EmailService::sendWelcomeWithCredentials()` | Пароль передаётся в метод открытым текстом и используется при формировании письма; надёжного отложенного повтора из одной только отметки об ошибке нет. Для ручного зачисления во время обслуживания требуется отдельное решение выдачи учётных данных, без сохранения пароля в небезопасной очереди. Аналогично результат `sendCourseGranted()` вызывающая операция может не повторить автоматически. |
| `PublicExamsModule::ensurePages()` на `init` | При включённом модуле и отсутствии флага завершения вызывает `SubjectPagesService::ensureForSubject()` для предметов и записывает опцию готовности. Это автоматическая запись, запускаемая обычным HTTP-запросом, а не cron; её необходимо отложить. |
| `ExamGuestPageController::handleSignupPage()` → `GuestPageAccessService::invitationPage()` | GET с `pay` вызывает `openPayment()` и `WooExamAdapter::addToCart()`; GET с ключом или классом открывает гостевую сессию, а открытие формы пишет аудит. Проверять ветви по их действию, а не разрешать маршрут целиком как чтение. |
| `ExamGuestPageController::handleEntryPage()`, `handleResultPage()`, `handleReportPage()` | GET с ключом обменивает его на гостевую сессию (`openEntry`, `openResult`, `openReport`), неуспешная попытка меняет rate limit; без ключа проверяется существующая сессия. Требуется решение о новых гостевых сессиях и отдельно проверка остальной цепочки рендеринга. |

Эти выводы сделаны статическим чтением исходников, а не проверкой с реальной БД, транспортом почты или работающими внешними процессами. Полный список безопасных чтений и подтверждение остановки внешних процессов остаются открытыми.
