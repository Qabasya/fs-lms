# Этап 2. Создание мастер-класса, аккаунты, страница, флаеры

Зависимости: этап 1 (схема, репозитории, писатель журнала, подстраница), этап 0 (`lessonProblems`, `generateReadable`, Ш4).
Результат: офис создаёт и правит мастер-класс, добирает аккаунты порциями с прогрессом, печатает флаеры, продлевает, помечает к удалению,
снимает блокировки класса, **смотрит список аккаунтов мастер-класса** (решение 24); осмотрены места ядра, где ученики перечисляются (п. 2.7). Тика и плеерной части ещё нет.

Перед началом прочитать `README.md`, `../SPEC.md` §2 (решения 2–7, 14, 17, 21, 23, 24), §4, `../CONTRACTS.md` §8 (`MasterclassService`,
`MasterclassAccountService`), §9 (`MasterclassAdminController`), §10–§11. Образцы страницы: `inc/Modules/AdSync/` (`assets/admin.js`, шаблоны).

**Порядок:** 2.1 → 2.2 → 2.3 → 2.4 → 2.5 → 2.7 → 2.6 (аудит 2.7 может потребовать правок ядра — до живой проверки).

## Статус

Не начат. **Переписан по факту этапа 1 (2026-10-28):**

- Готово и проверено (этап 1): схема, `MasterclassConfig` (+ `normalize()`), энумы, DTO, три репозитория, `MasterclassLogWriter`, `MasterclassSettingsController` (вкладка, карточка Dashboard,
  тумблер), `MasterclassIntegrityController` (Ш4), `MasterclassAdminController` (подстраница и заглушка `templates/admin-page.php`). Этап 2 **достраивает** контроллер и шаблон страницы, а не создаёт их.
- Репозитории: всё, что нужно сервисам этапа 2, уже есть — `MasterclassRepository::insert/update/find/page`, `MasterclassAccountRepository::insertPending/attach/markDeleted/pageByMasterclass/
  liveUserIds/funnel/countByMasterclass`; методы с условным `UPDATE` возвращают `bool`. Отсутствие — только то, что перечислено ниже в 2.2 как «новое» (проверять `grep`-ом перед добавлением).
- `MasterclassService::serviceGroupIds()` **не нужен**: Ш4 уже читает `activeGroupIds()` в `MasterclassIntegrityController` (кеш на запрос — в `ServiceGroupResolver`).
- Журнал: `MasterclassLogWriter::write( MasterclassLogAction, array )`; актор — пользователь запроса, если не задан `actor_type`; пароли из `context` вырезаются, но класть их туда всё равно нельзя.
- Время: колонки модуля — UTC; `starts_at`/`ends_at` формы — местное, переводит `ExamTime`. `created_at`/`updated_at` в репозиториях пишутся явно, не `DEFAULT CURRENT_TIMESTAMP`.
- Форма берёт окно по умолчанию из `MasterclassConfig::startTime()/endTime()` (пара всегда валидна), а размер пачки — из `batchSize()`; `CHUNK_MAX = 25` — предел одного AJAX-вызова, не настройка.
- Ответ об ошибке AJAX — **строка** (`wp_send_json_error( $message )`): JS читает `res.data`, а не `res.data.message`; при `E-SESSION` nonce чинит перехватчик `nonce-refresh.js` только в бандле ядра —
  у модульного `admin.js` его нет, поэтому при 403 / `E-SESSION` скрипт должен сам показать «Сессия устарела — обновите страницу» (текст приходит в `data.message`).
- Шаблоны страницы подключаются `require` изнутри метода контроллера — свои переменные, коллизий с `settings.php` нет; но любую вкладку внутри «Настроек» отдавать данными с уникальным именем (правило модуля).
- Ловушки проверки: юнит-тест рендера **не заменяет** открытие страницы по HTTP (вкладка настроек падала на живой странице при зелёных тестах) — в 2.6 открыть **каждый** вид страницы и каждый экшен
  по HTTP. Кириллица в аргументах `curl` из Git Bash на Windows портится — слать `--data-urlencode` из файла или процентным кодированием. Скрипт подготовки cookie/nonce — образец:
  `zz_mk_e2e_prep.php` этапа 1 (выдаёт cookie администратора через `WP_Session_Tokens` и `Nonce::Config->create()`, возвращает опцию в прежнее состояние).

## 2.7 Аудит: где ядро перечисляет учеников и покажет «Ученик#N»

**Зачем.** Временные ученики хранятся в записях ядра (решение 24 `SPEC.md`: прогресс, сдачи, попытки, посещаемость, доступ и удаление завязаны на `persons` и
`student_records`), поэтому каждое место, где ученики перечисляются, надо осмотреть один раз и принять решение. Этап 0 закрыл четыре (выбор группы при зачислении, «Добавить в
открытую группу», выгрузка учеников, вкладка «Ученики»). Ниже — оставшиеся кандидаты, найденные по коду 2026-10-28; колонку «Решение» заполнить по факту проверки.

| Место | Предварительно | Решение |
|---|---|---|
| Центр печати: `PrintCenterService::searchStudents()` → `PersonRepository::searchStudents()` | скрывать учеников, у которых все записи в служебных группах (поиск «Ученик» иначе вернёт сотни) | |
| `StudentGroupCallbacks::ajaxSearchStudentsForGroup()` — подбор в открытую/общую группу | скрывать: добавлять временных некуда (`enrollOne()` их пропускает), в подборе они шум | |
| `StudentDirectoryService` — справочник учеников | выяснить, откуда берутся ученики и кому он нужен | |
| `DashboardService`, `AdminAlertService`, `NotificationService` (составы групп, счётчики, сигналы) | проверить: служебная группа не даёт сигналов «не ходит / не сдаёт», счётчики «учеников» не раздуты | |
| Состав группы мастер-класса: `GroupRosterService`, `JournalService`, `AttendanceService`, `PassedWorksService` («Работы»), `TaskAttemptReportService` | оставить (это состав самой группы); замерить время ответа на 500 аккаунтах; решить, нужна ли преподавателю работа мастер-класса в «Работах» («сдали N из M») | |
| `GroupsExportProvider` — выгрузка групп | решить: служебные группы целиком из выгрузки или с составом | |
| `StudentBundleExporter` — перенос предмета (ученики) | временные не должны попасть в пакет: проверить | |
| Подбор ученика к родителю и заявке (`ApplicationDataCallbacks`, `ParentLinkCallbacks`) | проверить: временные не предлагаются | |
| `ExamAudienceResolver` — аудитория экзаменов | уже не включает `isTrial` (решение 6 `SPEC.md`): подтвердить тестом | |
| AD-провижн (`AdSync`) | временные записи исключены (решение 6): подтвердить тестом, если модуль включён | |

**Правила.** «Скрыть» — через `ServiceGroupResolver` (не новый механизм), с тестом, а где есть SQL — с проверкой на `wp_db`. «Оставить» — с причиной в колонке «Решение».
Новое найденное место добавлять в таблицу, а не чинить молча.

**Готово, когда:** таблица заполнена, каждое «скрыть» реализовано и покрыто тестом; на стенде с 60 аккаунтами перечисленные экраны открываются и не показывают `Ученик#N`
там, где решено скрыть; время ответа экранов состава группы на 500 аккаунтах записано здесь.
