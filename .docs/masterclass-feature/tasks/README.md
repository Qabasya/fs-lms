## Правила работы (из корневого `CLAUDE.md`)

- **Проверки перед словом «готово»** (раздел «Правила качества»): PHPUnit (локально: `php -d extension=sodium -d extension=fileinfo
  -d extension=pdo_sqlite -d extension=sqlite3 vendor/bin/phpunit`, либо в контейнере `docker exec -w
  /var/www/html/wp-content/plugins/fs-lms wp_app php vendor/bin/phpunit`); загрузка DI (`docker exec wp_app php /var/www/html/wp-content/plugins/fs-lms/tests/stand/di-boot-check.php on|off` —
  каждый сервис из `Init::getServices()`); PHPStan уровня 5 по файлам этапа; `npx eslint .`; `npx stylelint "src/scss/**/*.scss"`;
  `npx gulp build`; всё про БД, блокировки и гонки — на **настоящей MariaDB** (`wp_db`), не на моках. Что не проверено — в отчёте прямо.
- **Не править код во время прогона** стенда или e2e (правка посреди прогона роняет сайт и портит результат).
- **Граница модуля.** В ядре нет слова «мастер-класс»: проверка этапа — `grep -rni masterclass inc --exclude-dir=Modules` пуст
  (после этапа 0 это закреплено тестом-сканером). Ядро знает один класс — `MasterclassModule` (строка в `Init::getServices()`).
- **Сначала существующее, потом новое**: образцы — `AdSync`, `VideoLibrary`, `PublicExams`; модуль не заводит слоёв и статических утилит.
- **Нет несуществующего.** Имена, колонки, статусы — только из кода и `CONTRACTS.md`; спека сверена с `master` 1.1.85 (`SPEC.md` §16).
- **Исправление ошибки — это и правило**: класс ошибок → строка в `inc/Modules/Masterclass/CLAUDE.md` и тест.
- **После этапа — переписать следующий** по факту: имена, готовые точки расширения, что оказалось лишним.
- Временные файлы в контейнере — с префиксом сессии (`zz_mk_…`), чистить по точным именам; временные пользователи стенда —
  `zz_mk_…`, удалять по точным id.
