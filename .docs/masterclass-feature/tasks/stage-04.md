# Этап 4. Тик и удаление

Зависимости: этапы 1–3 (аккаунты, заморозка, журнал), этап 0 (Ш3).
Результат: каждые 15 минут модуль пишет в журнал заморозку, удаляет неиспользованные и просроченные аккаунты порциями, сносит группу, когда удалять некого,
подчищает зависшие строки и старый журнал; удаление группы любым путём не оставляет учёток `student-N`; «Удалить» на странице работает (отложенно).

Перед началом прочитать `README.md`, `../SPEC.md` §2 (решения 5, 7, 16, 18, 19), §4 («Тик»), §8, §9, `../CONTRACTS.md` §8 (`MasterclassLifecycleService`), §9
(`MasterclassCronController`, `MasterclassIntegrityController`).

**Порядок:** 4.1 → 4.2 → 4.3 → 4.4 → 4.5.

## 4.1 `MasterclassLifecycleService`

- [ ] `tick()` (шаги под `step()`: сбой одного шага логируется и не останавливает остальные) = `logFreezes()` → `purgeUnused()` → `purgeExpired()` → `dropGroups()` →
  `sweepStale()` → `purgeLog()`. Бюджет `ACCOUNTS_PER_TICK = 60` общий на удаления (шаги 2–3); каждый шаг идемпотентен и не выбирает обработанное
  (`unused_purged_at`, `purged_at`).
- [ ] `purgeExpired()`: аккаунт с живой заявкой при `delete_requested_at` → `detachAccount()`, иначе пропуск; остальные → `deleteAccount()`. `dropGroups()`: группа
  удаляется (`DeleteGroupEvent`), только когда живых аккаунтов нет (или все отвязаны); живёт, пока жив хоть один аккаунт с заявкой.
- [ ] `onGroupDeleting()` (Ш3, синхронно): живые аккаунты — с заявкой отвязать, `Enrolled` пропустить, остальные удалить; затем `markPurged()`.
  `onUserDeleted()` (`deleted_user`): `markDeletedByUserId( UserDeleted )`; журнал только если поставилось.
- [ ] Тесты: бюджет, идемпотентность каждого шага (повторный тик ничего не делает), отвязка при `delete_requested_at`, группа не удаляется при живом аккаунте с заявкой,
  `onGroupDeleting()`, `onUserDeleted()` (уже помеченный аккаунт не трогается), `purgeLog()`.

**Готово, когда:** тесты зелёные.

## 4.4 Проверки на настоящей MariaDB и из крона

- [ ] Два тика одновременно — работает один (замок); `markFrozen()` ставится один раз; бюджет соблюдается при 200 аккаунтах (несколько тиков).
- [ ] **Удаление из WP-Cron, не из AJAX:** `wp cron event run fs_lms_masterclass_tick` реально удаляет аккаунты (предусловие §11 п.1 проверено вживую).
- [ ] Удаление группы со страницы «Группы» и сносом предмета не оставляет учёток `student-N`, записей, физлиц (Ш3); аккаунт с заявкой отвязан, а не удалён.
- [ ] Данные ученика по занятию удаляются вместе с группой (`GroupDeletionHandler` по `group_lesson_id`), отдельной чистки нет.

**Готово, когда:** все четыре пункта проверены на стенде, остатков нет (проверить SQL по точным id).
