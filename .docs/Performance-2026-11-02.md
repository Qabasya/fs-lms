# Замеры оптимизации кабинета — 2026-11-02

Исходное состояние: `88d0d41e`. Среда: локальные WordPress/PHP 8.3, MariaDB 10.6, Docker. Это профиль серверных сервисов через CLI, **не TTFB и не длительность HTTP/AJAX**. SAVEQUERIES добавляет накладные расходы. Рабочие учебные данные не изменялись.

Повторение:

```bash
docker exec -i wp_app php < tests/smoke/profile-performance.php > /tmp/fs-lms-profile.json
```

Профайлер выбирает ученика с наименьшим и наибольшим числом занятий (при равенстве — по ID), первого родителя и администратора. На обоих замерах у учеников 3 и 22 занятия; база между замерами не менялась. После изменения состава/истории автоматический выбор может измениться: перед сравнением проверить набор. Отчёт не содержит имён, контактов, логинов, ответов или текста SQL.

На сценарий выполняются четыре повтора с новым DI-контейнером. Первый очищает только локальный объектный кеш процесса; внешнее хранилище кеша не очищается, буферы БД не сбрасываются. Контекст авторизации готовится до замера сервиса. Ниже медиана трёх повторов с прогретым объектным кешем. Родительский профиль — данные выбранного по умолчанию ребёнка. В ленте «Работы» подтверждено сокращение SQL 28 → 10, в профиле большой истории — 113 → 97. Размеры JSON одинаковы. Время профиля на этом прогоне выросло: сокращение SQL не доказывает ускорение всей страницы. Пакетная загрузка также немного увеличивает пиковую память большой истории. Для выводов о пользовательской скорости нужны отдельные HTTP-прогоны без конкурирующих проверок, больше повторов и большая история.

Изменения:

- Дедлайны получают сдачи выбранного ученика одним запросом на пакет до 500 канонических progressId, вместо чтения по каждому занятию. Порядок сдач внутри занятия и правила статусов сохранены.
- Лента «Работы» пакетно читает строки занятий и агрегатные сдачи только окна просмотра (до 40 строк/пар); технические строки дополнительного занятия используют общий контекст. Ростер и имя группы переиспользуются в пределах порции. Карточка учеников и операции зачёта продолжают работать по прежним правилам.
- Пакетные репозитории исключают пустые/повторные ID, делят 501 уникальный ID на два запроса; проекция посещаемости и канонический прогресс продолжений сохранены. Изменений схемы и постоянного кеша нет.

Проверка: полный `npm run ci` — 4412 PHP-тестов / 13796 assertions, 367 JS-тестов. Остаются существующие предупреждения: 126 Stylelint, PHP/PHPUnit — 1 warning, 1 deprecation, 9 PHPUnit deprecations, 1914 notices, 5 skipped. PHPCS всего затронутого наследуемого кода не проходит из-за существующих нарушений; это не часть npm CI. Целевые тесты репозиториев/сервисов — 130 тестов / 435 assertions. `tests/smoke/passed-works-db.php` — 17 PASS на временных таблицах MariaDB: пагинация, отдельные/пакетные выборки, область ученика, задачи, посещаемость и продолжение. Профайлер не заменяет эти проверки корректности.

Следующие измеренные кандидаты:

- В большом профиле остаются 20 чтений сдачи через `find()` (URL и отметки одной записи), 10 чтений отметок задач и 10 чтений занятия из источника оценок. Это оставшаяся часть O4.
- Главная сотрудника остаётся на 63 SQL: повторные ростеры, занятия, замены и названия групп требуют общей загрузки фактов (O3/O4).
- O0 ещё требует HTTP/DOM-профиля и журналов, отдельного преподавательского сценария, большей истории и планов EXPLAIN. O1 — браузерной приёмки переходов, фильтров, прокрутки и смены ребёнка. O2/O4 и индексы без этих данных не объявляются завершёнными.

## O6 — общие оптимизации по измерениям (2 ноября)

- **Bootstrap плагина** (`tests/smoke/profile-bootstrap.php`, атрибуция SQL wp-load к плагину по стеку SAVEQUERIES): 17 SQL на любой запрос (публичная страница, `/profile/`, AJAX — bootstrap одинаковый), все — чтения `wp_options` (флаги модулей + гейты миграций), суммарно ~1.4 мс. Конструкторы сервисов данных не читают. Кандидат «autoload у горячих опций» (~15 чтений) не внедрён: 1.4 мс не подтверждено узким местом.
- **Пакетные исправления подтверждённых N+1**: журнал открытой группы (ячейки «+» — пакетный `LessonProgressService::completedLessons` вместо `isLessonCompleted` на каждую ячейку; программа читается одним `listByGroup`), оболочка курса `CourseNavService` (пакетная карта завершённости), экспорты лиц (`findByIds` + per-request кэш групп), экспорт групп (пакетные `countActiveByGroups`/`displayNames` по порциям 500), словарь работ `WorkManager::prime` перед чтением эффективных работ. Счёт: журнал открытой группы S×L×~4 → S×3 + 1 SQL; оболочка курса ~5×L → ~3 на программу.
- **Ассеты**: админка гейтится по экранам, изоляция SPA-бандлов сохранена, polling-отсутствие подтверждено (интервалы — UI-таймеры и синхронизация экзаменов). Базовый фронт-стек на всех публичных страницах оставлен: шорткоды плагина могут стоять на любой странице темы; гейтинг без HTTP-профиля веса страницы не оправдан.
- **Heartbeat видео**: порция 1/мин на зрителя — чтение занятия + `canWatch` + сессия под GET_LOCK. `tests/smoke/video-access-db.php` на MariaDB: 8 конкурентных соединений → одна rolling-сессия, 80 инкрементов и 4800 секунд без потерь, изоляция по бакету, EXPLAIN ищущего запроса — `key: user_key`, `type: range`, 3 строки на таблице из ~1000. Клиент: порции аддитивные, сетевой сбой без повтора (без двойного счёта), хвост — sendBeacon best-effort, nonce-интерсептор ретраит 403.
- **Проверки**: `npm run ci` — 4423 PHP-теста / 13831 assertions (без падений; прежние warnings/deprecations/notices/5 skipped сохраняются), 367 JS-тестов, exit 0. Целевые тесты журнала/курса/экспортов — 37 тестов / 130 проверок; видео-smoke — 6 PASS. `FakeWpdb` отвечает на GET_LOCK/RELEASE_LOCK сам (именованные блокировки — шов конкурентности, не бизнес-SQL); юнит-стенд на SQLite их не поддерживает, рантайм-поведение на MySQL/MariaDB не изменено.
