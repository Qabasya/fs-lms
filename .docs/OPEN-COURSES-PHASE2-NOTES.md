- Новые отдельные ключи `PostMetaName`: `CourseSelfPacedEnabled` (false), `CourseAudienceSubjectKeys` ([]), `CourseServiceGroupId` (0). Имена проектируемые. Не смешивать их с заменяемым массивом `PostMetaName::Meta`, содержащим modules.

- Для группы предпочтительна nullable колонка `self_paced_course_id bigint unsigned`, UNIQUE, default NULL. Это явный SQL-признак и атомарная уникальная связь; обычные группы имеют NULL, не 0. Служебная группа: open, is_shared=0, без расписания. Существующий course_id сохраняется для API назначения. Обратную мета-ссылку проверять на согласованность с колонкой.
- Пропущенные поля старого клиента означают «сохранить», а не false/[]/0. Передавать настройки как nullable patch.

## Создание группы и атомарность

Отдельный сервис подготовки при явном включении, не при buildTree/просмотре:

1. Проверить область редактора, аудиторию и OpenCourseValidator.
2. Транзакция и сериализация по course ID: row lock существующего поста через Manager/Repository либо инкапсулированный GET_LOCK. Под блокировкой повторно читать состояние.
3. Найти/создать одну группу с UNIQUE self_paced_course_id. Не переиспользовать произвольную старую open-группу автоматически.
4. Назначить курс существующим CourseAssignmentService, сохраняя строки с прогрессом, без Replace.
5. Проверить полноту фактически созданной программы и обе связи. Ошибка — rollback; сбросить WP meta/object cache после rollback.

Риски существующих API:

- `GroupLessonRepository::add` игнорирует false результата insert, возвращает insert_id. Одной транзакции вокруг assign недостаточно: нужно обеспечить исключение/проверку фактической записи.
- `GroupsRepository::create` возвращает 0, update — bool; проверять результаты.
- `PostManager::updateMeta` возвращает void; отсутствие exception не доказывает запись меты.
- `TransactionRunner` не поддерживает вложенные транзакции.
- `CourseAssignmentService::assign` синхронно dispatch CourseAssigned; LearningEventSubscriber пишет журнал. Проверить границу транзакции и post-commit эффекты.
- `syncCourseLessons` уведомляет об изменении программы. Не использовать обычное зачисление ради подготовки и не вводить скрытый обход глобальных хуков.

## Гарды публикации и изменений контента

`CoursePublishValidator` проверяет пустые шаги, но не самостоятельную автопроверку. Добавить строгий OpenCourseValidator только для нового self-paced сценария при включении и публикации, сохраняя поведение старых open-групп.

Проверка только кнопки «Доступ» недостаточна. Аудитировать мутации структуры в CourseBuilderService/Callbacks, LessonManager и его handlers, WorkManager и handlers, обновления assessment/task, публикацию через обычный WP редактор и импорты. Для опубликованного self-paced курса изменения зависимых сущностей должны проверять candidate-состояние до записи, чтобы ручная проверка не стала доступна ученикам. ContentUsageService даёт обратные связи; GroupsRepository::findByCourse — назначенные группы. Не ограничиваться AJAX-публикацией одного курса.

`ExamAudienceResolver` исключает is_shared, но пока не служебные группы. Оба пути отбора аудитории должны исключать self_paced_course_id != NULL до включения самозаписи, иначе курс сам выдаст ученику предметный допуск. Аналогично проверить основной record для профиля, зачисления и AdSync в следующих фазах.

## Проверки фазы

- DTO/Manager roundtrip; сохранение структуры и заголовка не стирает настройки; старый клиент без полей сохраняет их.

- Клонирование и оба формата переноса не копируют локальную group-связь; неизвестные subject keys отфильтрованы безопасно.
