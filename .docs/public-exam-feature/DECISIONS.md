# Решения по экзаменам

Актуально на 2026-10-01. Основная спецификация — [SPEC.md](SPEC.md). Последние ответы пользователя имеют приоритет над ранними предложениями и прикреплёнными замечаниями.

## Ответы на первоначальные вопросы

| № | Вопрос | Итог |
|---|---|---|
| 1 | Когда открывать баллы и разбор? | Пользователь: гостю сразу после сдачи, своему ученику после утверждения работы преподавателем. Ожидания всех сеансов нет. Ручная часть до проверки имеет pending, не фиктивный окончательный балл. |
| 2 | Когда неявка? | Пользователь: по окончании планового сеанса, если экзамен не начат. 10:00 + 3:55 → 13:55. Не через 15/30 минут. |
| 3 | Подтверждение гостя и доставка результата? | Пользователь: результат на площадке, позже ссылка отправляется сотрудником лично в мессенджере. Никаких гостевых уведомлений. Пользователь предложил выдавать персональную ссылку на площадке, как JOIN. В SPEC выбран этот сценарий без OTP/короткого кода. |
| 4 | Кто записывается и управляет? | Пользователь: после публикации все ученики преподавателя, управление у него и администратора всегда. SPEC уточняет предметный scope и отдельный переключатель гостевой формы. |
| 5 | Каналы уведомлений? | Пользователь: всё в личном кабинете, гостям ничего. SPEC: ученику/родителям in-app, гостевые события в аудите без доставки гостю; напоминания 18:00 накануне и за 60 минут как настройки v1. |
| 6 | Родитель, Control, дизайн? | Пользователь: родитель только смотрит; контрольные остаются шагами курса; задачи как сейчас в «Работах». Полный экран разбора, общий renderer, не модалка/отдельный дизайн. |
| 7 | Время опоздавшего? | Пользователь: полная длительность с фактического старта. Плановый конец закрывает новые старты и определяет неявку, но не завершает начатые попытки. |
| 8 | Свободный PublicExams и резерв? | Прямого отдельного ответа о свободном режиме не было. Проектное решение v1: существующий свободный режим сохранить отдельно. Резерв доступен, но не обязателен; требование гостевого немедленного разбора важнее прежнего предложения ждать последнего сеанса. |
| 9 | Домашняя тренировка? | Пользователь (раунд 2): домашних тренировок нет. Кнопок перерешивания и тренировочного API не делаем. |

## Дополнительные решения спецификации

- Отдельный exam_participant с необязательным Person; автоматического зачисления гостя нет.
- Гостевые entry/result/report/invitation ключи разделены, выдаются вручную, хранятся хешами. Подход JOIN переиспользуется, его предметные сроки и обработчик — нет.
- Смена/самоотмена до начала своего сеанса. Нет листа ожидания в v1.
- Ответственный по умолчанию владелец проведения; новый общий доступ всем преподавателям не вводится.
- Вместимость из RoomDTO с меньшим лимитом сеанса при необходимости. Кабинет занят ровно на плановое окно сеанса (для ЕГЭ 10:00–13:55), без резерва под поздние старты (раунд 2).
- Полного снимка банка в v1 нет. Фиксация небольшого конфига + защита всей цепочки используемых данных, не только списка task_id.
- Согласие на передачу школе отдельно, участие без него возможно. Маркетинг отдельно и необязателен. Согласие представителя несовершеннолетнего не заменяется чекбоксом самого ребёнка.
- Срок хранения гостей 365 дней и срок школьного отчёта 90 дней — настраиваемые продуктовые значения по умолчанию, не юридические нормы.
- Экспорт/печать ПД требуют оба существующих права. Школьный отчёт v1 только для просмотра, без публичного CSV.
- Формальная система апелляций не включена; изменение результата с причиной и журналом включено.
- Плеер-схема удалён из мокапа. Реальный плеер КЕГЭ/ОГЭ сохраняется; разработка нового мобильного движка не заказана.

## Что отменено из старых материалов

Email/OTP гостям; напоминания гостям; автоматическая рассылка в мессенджер; неявка через 15 минут после начала; правило «отметка прихода отменяет неявку»; обязательное ожидание всех сеансов; обязательный резервный вариант; запись родителем; самостоятельная публичная CSV-выгрузка школьному преподавателю; модальное окно вместо полноценного разбора; 22 первичных = 72 вторичных; обязательный телефон при наличии другого контакта.

«Приходите за 15 минут» — только организационная рекомендация перед началом, не окно допуска после старта.

## Последние правки макетов

- Только очные сеансы, без онлайн-формата.
- Форма записи остаётся обсуждаемым черновиком, не окончательным UI-заданием.
- «Проведение экзамена» — первый пункт «Мои экзамены» преподавателя.
- В школьном отчёте работа раскрывается под таблицей на той же странице: навигация по заданиям, затем задания.
- Карточки показателей в отчёте и статистике выровнены по размерам.
- Плеер-схема удалён; используется существующая станция.
