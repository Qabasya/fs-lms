# Решения по экзаменам

Актуально на 2026-10-02. Источник — последние ответы и актуальная [SPEC.md](SPEC.md). Этот файл пересобран по текущей спецификации, включая изменения, внесённые после первоначальных мокапов.

## Подтверждённые требования

1. Экзамены отделяются от курса. **Control остаётся шагом курса.** Админский конструктор работ сохраняется.
2. Проведение имеет произвольный период, например 4 или 10 дней; в день может быть несколько сеансов. Участник сдаёт в один выбранный сеанс.
3. Только очный формат. Дополнительные очные даты после болезни допустимы; онлайн исключён.
4. Преподаватель публикует экзамен и даты; записываться могут все ученики, зачисленные в группы соответствующего направления: для предмета ЕГЭ — группы предмета ЕГЭ, для предмета ОГЭ — группы предмета ОГЭ (они уже разные предметы). Управляют преподаватель (в рамках своих предметов), методист и администратор платформы; администратор — всегда.
5. Родитель только смотрит данные своего ребёнка; не записывает, не отменяет и не начинает экзамен.
6. Гость получает разбор сразу после сдачи. Ученик центра — после явного утверждения работы преподавателем.
7. Неявка фиксируется **в конце планового сеанса**, если попытка не начата. Пример: 10:00 + 3:55 → 13:55.
8. Начавший получает полную длительность от фактического старта. Начал в 11:00 → дедлайн 14:55. В 13:55 такой участник продолжает, не считается отсутствующим.
9. Уведомления LMS — только в личном кабинете. LMS гостям сообщений не отправляет. Существующие письма WooCommerce о заказах/оплате сохраняются без изменений.
10. Гость видит результат на площадке; позже сотрудник **вручную** отправляет личную ссылку в мессенджере.
11. Преподаватель может отменить не начатую запись, чтобы ученик записался снова. Неявка также освобождает возможность повторной записи на будущий сеанс.
12. Задания должны выглядеть как сейчас в «Работах». Любое расширение их представления выполняется общим компонентом, не третьим независимым дизайном.
13. Фича реализуется в ядре (см. выше).
14. Кабинет занят на плановое окно сеанса — для ЕГЭ с 10:00 до 13:55, не дольше. Дополнительный резерв помещения под поздние старты не вводится (§3).
15. Домашних тренировок и перерешивания нет. Разбор — только просмотр результата.
16. Гость не может сам отменить или сменить сеанс: только лично через сотрудника.
17. Выдача и копирование ссылок (вход, результат, отчёт) не требует `ExportPII` и `ManageLmsPlatform`.
18. Экзамены не попадают в журнал, «Мои работы» и оценки группы; у ученика и родителя для них отдельный пункт меню «Мои экзамены», всегда видимый.
19. Права на экзамены: преподаватель в рамках своего направления (предметов), методист и администратор. Office и Market такого права не получают.
20. Утверждение работ массовое (§7). Школьный отчёт может включать и учеников центра, и гостей.
21. Согласия оформляются тем же механизмом, что в лид-форме заявки (§9).
22. Экзаменов-станций в курсах в проде нет: миграция старых связей не требуется (§14).
23. Гости записываются через ссылку школьного преподавателя и оплачивают специальный товар WooCommerce; до оплаты временная бронь, после серверного подтверждения — постоянная запись (§6).
24. Один товар/цена для всех; отдельные настройки товара для 9 и 11 класса могут указывать на один ID.
25. Переносы гостей и урегулирование проблем — лично через сотрудника. При полной неявке возврат вне WooCommerce; письма и существующий checkout WooCommerce не менять.
26. **На гостевой форме капчи нет** (2026-10-02): гости заходят с VPN, и задание Яндекса оттуда не открывается — форма не отправлялась бы, клиент терялся бы. Защита: ссылка с уникальным ключом (форма не публичная), honeypot и проверка скорости заполнения, лимиты по IP с запасом на школу (§6).
27. Страница формы доступна только по ссылке с ключом, не индексируется; ключ обменивается на куку с редиректом на адрес без ключа (Метрика не видит ключ). Ссылку можно перевыпустить — через модалку с подтверждением (§6).
28. Доступ гостя — только через оплату WooCommerce. Бесплатный допуск — только купоном скидки, который создаёт владелец в WooCommerce; заказ с нулевой суммой считается оплаченным так же, как обычный. Обхода оплаты в LMS нет, в том числе у кнопки «Добавить гостя».
29. Об «Оплачено, требуется помощь» и сбое сверки оплаты уведомляются **все пользователи с ролью «Администратор платформы»** (`lms_office`, сейчас двое) в ленте их кабинета. Им выдаётся узкое право разбирать оплаты гостей (`ResolveExamPayments`): очередь, перенос оплаченного гостя, отметка возврата вне WooCommerce. Управление проведениями им по-прежнему не выдаётся.
30. Параметры реализации из списка ниже подтверждены владельцем 2026-10-02.


## Уточнения по оплате гостя

- **Факты прод-магазина (2026-10-02):** WooCommerce 11.1.2, классический checkout, HPOS без режима совместимости, гостевой checkout включён (учётки не создаются), шлюз «Умный платёж» (ЮKassa), оплаченные заказы — в «Обработка». Следствия для плана: 0.7 (dev на ту же версию), 0.8 (объявить HPOS-совместимость), 11a.5 (классические хуки, `is_paid()`). Подробно — SPEC §6.

- Источники создаются в модалке проведения: школа, класс 9/11, ФИО преподавателя, персональная ссылка формы. Школьный преподаватель не получает автоматически доступ к работам.
- До оплаты сохраняется заявка и временно удерживается место. После серверного подтверждения оплаты — окончательная запись.
- Поздняя оплата без доступного места: ручной подбор сеанса или урегулирование сотрудником, без сверхброни.
- Переносы/неявки обсуждаются лично. При полной неявке возврат вне WooCommerce; автоматического refund нет.
- Один товар и цена. Два значения для 9/11 могут указывать на один товар; возможность разделить позднее.
- Общая ссылка делается через источник с данными организатора.
- Checkout и экран после оплаты уже настроены в WooCommerce. Письма WooCommerce не менять. LMS добавляет только фактический статус экзаменационной записи.
- Вход выдаёт сотрудник уникальной ссылкой, без логина и пароля.

## Параметры реализации — подтверждены владельцем 2026-10-02

- Hold 20 минут с ограничением временем записи/старта.
- ID товаров в настройках LMS, а не отдельные дублирующие URL в теме.
- Телефон обязателен; для ручной связи можно использовать его же. Отчество при наличии.
- Одна незавершённая экзаменационная заявка на корзину; за второго ребёнка оформление после первого заказа.
- Неоплаченные заявки очищаются через 30 дней, кроме несверенных оплат/открытых разборов; Woo-заказы не удаляются этой очисткой.
- Ручное добавление гостя не обходит оплату; бесплатный допуск — только купоном WooCommerce (решение 28).

## Что больше не применять

Капча на гостевой форме; гостевая запись без оплаты как основной поток; бесплатный допуск кнопкой в LMS; откладывание всех правил гостевой формы; запрет писем WooCommerce; онлайн-сеансы; плеер-схема; домашняя тренировка; резерв помещения сверх планового окна; автоматическая запись по банковскому редиректу; возврат через API WooCommerce; автоматическое восстановление отменённой записи по повторной оплатной нотификации.

Карточки дат с частично видимой следующей карточкой, стрелками и drag остаются в обоих интерфейсах. У гостя теперь «Перейти к оплате», у ученика «Подтвердить запись».

Все точки непонимания и их предотвращение — [E2E-REVIEW.md](E2E-REVIEW.md).
