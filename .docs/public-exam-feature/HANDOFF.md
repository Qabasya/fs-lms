# Передача владельцу: эксплуатация экзаменов

Файл создан на этапе 9, дополнен на этапе 13.7. Что проверено и что нет — `ACCEPTANCE.md`; устройство — `SPEC.md`, `tasks/README.md`.

## Серверный cron экзаменов

Неявка, автоистечение попыток, напоминания, освобождение броней и доставка уведомлений работают от минутных тиков WP-Cron
(`fs_lms_exam_auto_expire_tick`, `fs_lms_exam_hold_release_tick`, `fs_lms_exam_outbox_tick`). WP-Cron срабатывает только при посещении сайта,
поэтому для минутной точности его запускает системный cron.

1. В `crontab` пользователя веб-сервера:

   ```
   * * * * * curl -fsS -m 50 "https://<домен>/wp-cron.php?doing_wp_cron" >/dev/null 2>&1
   ```

2. В `wp-config.php` (чтобы WordPress не запускал cron на каждое посещение дополнительно):

   ```php
   define( 'DISABLE_WP_CRON', true );
   ```

**Что будет без системного cron:** неявка, автоистечение, напоминания («завтра», «скоро начало», «вход открыт»), освобождение броней гостей и
уведомления будут срабатывать с задержкой до следующего посещения сайта. **Допуск к старту от cron не зависит**: его проверяет сервер в момент
запроса (окно сеанса и личный дедлайн), поэтому задержка тика не открывает просроченный старт и не продлевает его.

### Как проверить на сервере

```
wp cron event list --fields=hook,next_run_relative | grep exam
```

Должны быть три хука — `fs_lms_exam_auto_expire_tick`, `fs_lms_exam_hold_release_tick`, `fs_lms_exam_outbox_tick`; следующий запуск каждого — в пределах минуты.

Ручной запуск (тот же код и та же блокировка, что у cron; второй одновременный запуск не выполняется):

```
wp fs-lms exam tick --name=auto-expire    # автоистечение, неявки, завершение проведений, напоминания
wp fs-lms exam tick --name=hold-release   # брони гостей, сверка оплат, очистка ключей идемпотентности
wp fs-lms exam tick --name=outbox         # доставка событий в ленту уведомлений
```

### Границы настройки

- Cron на проде настраивает владелец по этой инструкции; плагин инфраструктуру сервера не меняет. На dev — ручные запуски `wp fs-lms exam tick`.
- Расписание общего тика уведомлений кабинета `NotificationsTick` (раз в 15 минут) **не менялось**: минутными стали только новые экзаменные тики.
- Время «завтра экзамен» (18:00) и «скоро начало» (за 60 минут) — константы `ExamReminderService::TOMORROW_AT` и `SOON_MINUTES`; в настройки их вынесут по просьбе владельца.

## Ограничения гостевой оплаты

- **Блочное оформление WooCommerce (Store API) не поддерживается:** хуки корзины и оформления рассчитаны на классический checkout (так настроен прод). При переходе на блочный checkout гостевая запись перестанет привязывать позицию к заявке.
- Оплату подтверждает только сервер WooCommerce (`WC_Order::is_paid()`); возврат из банка без оплаты запись не подтверждает.
- Для оплаты нужен виртуальный товар экзамена (настройки → «Экзамены для гостей»); до выбора товара и прохождения чек-листа проведение с гостями не публикуется.

## Настройки запуска гостевой записи

Настройки — раздел «Экзамены для гостей» в настройках конфигурации плагина (`PluginConfig`, методы `exam*`; шаблон `settings-7-config.php`):

1. **Товары WooCommerce** для 9 и 11 класса — виртуальные товары; цена берётся из магазина, не из LMS. Без выбранного товара гостевую запись включить нельзя.
2. **Срок брони** (минуты), **лимиты** (активных броней с одного адреса, заявок с адреса в час, активных броней на источник), **срок хранения** гостевых данных (по умолчанию 365 дней после завершения проведения) и **срок неоплаченных заявок** (30 дней).
3. **Контакты центра** (телефон, почта, часы) — показываются гостю на отказах и в «Спасибо»; тема может подменить их фильтром `fs_lms_center_contacts`.
4. **Согласия** — обработка ПД (обязательное), передача результата школе, маркетинг; тексты хранятся в согласиях платформы.
5. **Чек-лист готовности** (`ExamLaunchChecklist`) показывается в форме проведения; пока он не пройден, «Запись для гостей» не включается.

Страницы гостя создаются при активации и миграцией: `/exam-signup/`, `/exam-entry/`, `/exam-result/`, `/exam-report/` (шорткоды `fs_lms_exam_*`). Без ключа в адресе они отвечают 404 — это нормально.

## Вместимость кабинетов

Мест в сеансе не больше вместимости кабинета. **Заполните «Настройки → Кабинеты» до первого проведения:** у кабинета с `seats = 0` сеанс создать нельзя
(на dev кабинеты 315 и 317 заведены с нулём). Один кабинет — один сеанс в одно время (блокировка кабинета, `RoomAvailabilityService`).

## Роли и права

| Право | Кто | Что открывает |
|---|---|---|
| `manage_lms_exams` | преподаватель (свои предметы), методист, администратор | проведения, сеансы, доска, результаты, статистика |
| `manage_lms_exam_guests` | то же | источники, добавление гостя на месте, допуск, ссылка входа, удаление данных гостя (вместе с правом на раздел «Ученики») |
| `share_lms_exam_results` | то же | ссылка результата гостя, школьные отчёты |
| `resolve_lms_exam_payments` | офис, администратор | очередь «Оплачено, требуется помощь» |
| `export_pii` + `manage_lms_platform` | по решению владельца | выгрузка и печать списка участников |

Предметы ограничивает `ExamAccessGuard`, а не право. **Открытый вопрос:** методист без роли преподавателя пока не имеет витрины `/profile/` и уходит в wp-admin;
с экзаменами он работает только со второй ролью (`tasks/README.md` §8 п. 7, «Открыто» в `Tasks.md`).

## WooCommerce

- LMS **добавляет**: привязку позиции корзины к заявке (скрытое поле `fs_exam_application` + подпись), блок статуса записи на «Спасибо», отсчёт брони в корзине и оформлении, сверку оплаты по минутному тику.
- LMS **не трогает**: статусы и письма заказов, возвраты (`refund` не вызывается), состав и цену товара, чужие заказы. Заказы Woo не удаляются никогда, в том числе при обезличивании гостя.
- HPOS включён (без режима совместимости); блочное оформление (Store API) **не поддерживается** — см. «Ограничения гостевой оплаты».
- Оплата подтверждается `WC_Order::is_paid()`; возврат из банка без оплаты запись не подтверждает.

## Что делать сотруднику

| Ситуация | Действие |
|---|---|
| «Оплачено, требуется помощь» (оплата пришла, места нет) | «Мои экзамены → Оплаты гостей» → «Требуют помощи» → «Урегулировать»: перенести в сеанс **того же проведения** со свободным местом; «Деньги возвращены вне магазина» (сумма обязательна; деньги возвращаете вы сами, LMS заказ Woo не меняет и возврат не вызывает); «Другое» (только отметка). Причина обязательна. Урегулированные — вкладка «Урегулированы» |
| Гость потерял ссылку входа | доска сеанса → строка гостя → «Перевыпустить ссылку на вход» (прежняя перестаёт работать; начатая попытка не теряется) |
| Ссылку отдали гостю | строка гостя → «Отметить: ссылка … передана» (копирование отметку не ставит; в строке видно «Передана дата, кто») |
| Потеряна ссылка результата | строка гостя → «Скопировать ссылку результата (выдать новую)»; отозвать — «Отозвать ссылку результата» |
| Гость пришёл без записи | «Добавить гостя» → ссылка на оплату (показывается один раз; место держится до срока брони). Пока гость не оплатил, он виден в блоке «Ожидают оплаты» доски сеанса («Место удерживается до …»); потерянную ссылку выдают заново кнопкой «Скопировать ссылку на оплату» |
| Гость записан не на тот сеанс | доска сеанса → строка гостя → «Назначить другой сеанс» (преподаватель — `manage_lms_exams`; офис с `resolve_lms_exam_payments` переносит оплаченных гостей; в обоих случаях причина обязательна, гостю уведомление не отправляется) |
| Ссылка школы утекла | «Ссылки для преподавателей» → «Отозвать»: страница записи перестаёт открываться, старые заявки сохраняются |
| Школе нужен результат | «Результаты» → «Создать отчёт» (в отчёт попадают ученики с утверждённым результатом и согласившиеся гости) → «Скопировать ссылку» |
| Запрос гостя на удаление данных | строка гостя → «Удалить данные гостя» (нужны оба права, причина обязательна) |

## Хранение и удаление данных гостей

Ежедневный `fs_lms_retention_cleanup` (тот же, что чистит аудит) вызывает `ExamRetentionService::runDaily()` под блокировкой `exam_retention`:

- гость обезличивается, когда **все** его проведения завершены или отменены раньше срока хранения и нет открытого ручного разбора оплаты: отзываются ключи входа и результата и сессии, очищаются ФИО, телефон, мессенджер и их хеши, удаляются файлы ответов; **попытки, ответы и название школы остаются** (агрегаты); участник с `person_id` не трогается;
- заявки `expired_unpaid`, `failed`, `cancelled` старше срока очищают черновик и хеш адреса; заявки с несверенной оплатой, `paid_needs_resolution` и подтверждённые не трогаются;
- обработанные события outbox, истёкшие ключи и сессии старше 30 дней удаляются.

Ручной запуск: `wp cron event run fs_lms_retention_cleanup`. Срок показывается гостю числом из настроек; в текстах он не назван «установленным законом».

## Неизменяемость варианта

После первого старта (или начала сеанса по времени) состав, баллы, шкала и тексты заданий варианта не меняются: правка отклоняется нотисом
«Вариант используется в экзамене …». Для нового проведения сделайте **копию варианта**. Предмет с таким вариантом удалить нельзя (архивация допустима).
Подробности и список путей — `ACCEPTANCE.md`, «Неизменяемость».

## Диагностика

```
wp fs-lms exam selftest                                   # 7 проверок схемы на реальной базе
wp fs-lms exam tick --name=auto-expire|hold-release|outbox
SELECT type, attempts, last_error FROM wp_fs_lms_exam_events_outbox WHERE processed_at IS NULL;   # застрявшие события
```

Журнал «Ошибки» (кабинет): коды `X-*` — `X-FULL` мест нет, `X-HELD` места заняты бронями, `X-CLOSED` запись закрыта, `X-CONFLICT` пересечение, `X-STARTED` попытка уже начата,
`X-STALE` версия устарела, `X-LINK` ключ недействителен, `X-CONSENT` нет согласия, `X-ACCESS` нет прав, `X-NOT-OPEN` старт вне времени, `X-LIMIT` лимит, `X-ROOM` кабинет не подходит, `X-REPLAY` тот же ключ с другими данными.
Номер обращения (`ref`), который видит пользователь, ищется в журнале.

## Известные ограничения

- Блочное оформление WooCommerce не поддерживается; шлюз ЮKassa на прод-подобном стенде не проверялся (`ACCEPTANCE.md`).
- Гостю уведомления не отправляются (только кабинет); письма и SMS не заложены.
- Станция КЕГЭ/ОГЭ рассчитана на компьютер; на телефоне показывается предупреждение до старта, мобильного плеера нет.
- Страница результата гостя без сайдбара (курсы и статьи по ошибкам — решение записано в `tasks/stage-11b.md`, п. 11b.3.1, реализация отложена).
- Онлайн-оплата возвращается вне LMS: возврат делает сотрудник в магазине, LMS его не вызывает.
- Сверка `needs_resolution` повторно раз в 15 минут (11a.8.2), журнал формы (11a.2.7), чек-лист в форме проведения (11a.6.7) — не сделаны, см. статусы этапов.
