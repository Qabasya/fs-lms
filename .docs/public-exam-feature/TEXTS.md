# Тексты экранов: откуда берутся

2026-10-02. Проверка текстов макета: каждый текст — либо подставляется из данных, форм, настроек и менеджеров, либо осознанно захардкожен. Здесь же правило про род: в данных пола нет (в БД и формах нет поля «пол»), поэтому тексты о человеке пишутся без рода.

## 1. Подставляется (не хардкодить)

| Что в тексте | Источник |
|---|---|
| ФИО участника, телефон, контакт связи | форма заявки / `exam_participants`; ФИО выводится как введено |
| Школа, класс, ФИО школьного преподавателя | источник приглашения (`exam_sources`), не поле формы |
| Название проведения, период, вариант, ответственный | настройки проведения (`exam_events`) |
| Дата, день недели, время, кабинет, «осталось N мест» | `exam_sessions`, кабинет из `RoomRepository`; склонения — `Pluralizer::ru()` (PHP) и `pluralRu()` (`src/js/common/plural.js`) |
| «Начать можно до 13:55», «завершение в 14:55», «3 ч 55 мин» | `planned_end` сеанса и длительность формата (`EgeComputer` через фильтр), личный дедлайн попытки — **числа в тексте только шаблоном с подстановкой** |
| «27 заданий», «из 29 первичных», «из 100», «№26 и №27 по 2» | формат/шкала работы (`KegeScaleConfig` и контракт форматов, этап 0.3) |
| Условие, эталон, решение, «Ваш ответ» | банк заданий и ответы попытки |
| Цена «1 500 ₽», номер заказа, сумма | WooCommerce (цена — из товара, не из формы и не из LMS) |
| «Место удерживается до 14:20, осталось 19:41» | `hold_expires_at` с сервера; TTL — настройка |
| Срок доступа отчёта «до 30 ноября» | `expires_at` отчёта |
| Ссылка «Прочитать» у согласия | `ConsentDefinitionsRepository` (как в join-форме) |
| Подписи статусов (оплата / запись / допуск / попытка, вердикты, причины) | `label()` энумов, как у `AuthAction`, `LoginFailReason`, `ApplyFormField` |
| Названия ролей | `UserRole::label()` |
| Тексты уведомлений | `NotificationType` + серверные шаблоны с параметрами (ФИО, дата, сеанс) |

## 2. Контакты и настройки

**Контакты центра берём из темы сайта** (решение владельца 2026-10-02). Они уже есть в «Настройки темы» (`fs_lms_theme_site_settings`, класс `FS_LMS_Theme_Site_Settings`): `phone`, `email`, `hours` («с понедельника по субботу с 11.00 до 21.00»), `city`, `street`, ссылки на мессенджеры/VK. Плагин (ядро) тему напрямую не знает, поэтому:
- в плагине один небольшой сервис `CenterContactsService`, который отдаёт контакты через фильтр `fs_lms_center_contacts` (дефолт — значения из `PluginConfig`);
- тема подписывается на фильтр и отдаёт свои `phone`, `email`, `hours`, адрес (несколько строк в `FS_LMS_Theme_Site_Settings`);
- **если тема не отдаёт значение** — используется текст, который владелец вставит в настройки плагина (поле в `PluginConfig`, страница «Настройки»), как запасной вариант.

Адрес для резюме и подтверждения: город и улица из темы **до слова «каб.»** (в теме `street` = «ул. Черняховского, д. 6, каб. 316» — обрезается до «ул. Черняховского, д. 6»), номер кабинета — из выбранного кабинета сеанса (справочник «Настройки → Кабинеты»). Отдельное поле «Адрес проведения» не нужно.

Остальное, чего нет в `PluginConfig` (в нём сейчас только `consultation_url`, логотип и служебные флаги), — **добавить в существующий `PluginConfig` и его страницу «Настройки», не заводя новую опцию**:
- ID товаров `exam_product_9/11`, TTL брони, лимиты заявок (§6 «Защита гостевой формы»);
- получатели внутренних уведомлений об оплатах (по умолчанию все `lms_office`);
- запасные тексты контактов (см. выше).

## 3. Хардкод допустим

Заголовки и подзаголовки экранов, кнопки, пустые состояния, пояснения правил **без чисел и без рода** («Смена и отмена записи — до начала выбранного сеанса», «Не оплачивайте повторно», «Доступ только для просмотра»), подписи секций. Они лежат в шаблонах/JS как обычные строки интерфейса, как в остальном плагине.

## 4. Найдено в макете и исправлено или передаётся в работу

1. **Числа внутри статических фраз** — должны быть шаблонами с подстановкой, а не текстом: «до 13:55», «3 ч 55 мин», «20 минут», «27 заданий», «из 29 первичных», «осталось N мест», «до 20 мест», «60 активных броней», «до 30 ноября».
2. **Адрес и цена** в резюме перед оплатой — только из настроек и WooCommerce.
3. **Склонения** («осталось 6 мест / 2 места / 1 место», «N участника») — через `Pluralizer` / `pluralRu`, не руками.
4. **Род.** Исправлено в макете:
   - «Мария Алексеева сдала экзамен» → «Экзамен сдан: Мария Алексеева»;
   - «Гость Алина Орлова сдала экзамен» → «Экзамен сдан: Алина Орлова (гость)»;
   - действие «Пришёл» → «Отметить приход» (в SPEC и плане тоже);
   - метка состояния «Записан» в панели макета → «Запись подтверждена».

## 5. Правило формулировок (в SPEC §10, действует для макета, серверных текстов и уведомлений)

- Не использовать глаголы прошедшего времени и краткие формы единственного числа, согласуемые с полом человека: «сдал/сдала», «пришёл/пришла», «записан/записана», «ученик/ученица» (в тексте о конкретном человеке).
- Использовать существительное с известным родом: «Работа сдана», «Запись подтверждена», «Экзамен сдан: ФИО», «Приход отмечен», «Оплата получена».
- Обращение к самому человеку — на «Вы» во множественном числе: «Вы записаны на экзамен».
- Роль (Ученик, Родитель, Гость, Участник) — название роли, а не описание человека; его выводит `UserRole::label()` и не сочетается с согласуемыми глаголами.
- Тексты в `NotificationType` и энумах проверять на это перед добавлением.
