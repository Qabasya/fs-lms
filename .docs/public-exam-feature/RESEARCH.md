# Экзамены: аудит перед спецификацией

Дата: 2026-10-01. Обновлено после решений пользователя и приложенных замечаний. Исследован текущий код `fs-lms`, а не только HTML-мокап.
Статус: актуализирован после ответов пользователя. Основные требования — в SPEC.md; ответы и проектные решения — в DECISIONS.md. Аудит ниже описывает прежнее состояние кода до реализации фичи, а не целевое поведение.

## Подтверждённые требования пользователя

- Экзамены отделяются от шагов курса; создание работ остаётся в админке.
- Исправляются отступы `fs-field__label` и число стартовых позиций компьютерного ЕГЭ: 27.
- Один участник выбирает один сеанс проведения. Период произвольный: например, 4 или 10 дней. В один день бывает несколько сеансов.
- Только очный формат; дополнительная очная сдача после болезни допускается.
- У ученика и родителя появляется «Мои экзамены», с плитками, карточкой, результатами и переходом к выбранному заданию.
- До записи — «Записаться», после записи до открытия допуска — серая «Приступить», после открытия — активная.
- Вход в экзамен из уведомления, расписания и «Моих экзаменов».
- Преподаватель может отменить запись, чтобы ученик записался вновь. Неявка аннулирует запись автоматически. Повторная запись возможна при наличии свободных мест.
- Все значимые изменения сопровождаются уведомлениями. Обязательно: открытие записи, завтра экзамен, скоро начало, публикация результатов, аннулирование записи, пропущенный экзамен.
- Для гостей нужна предварительная форма; на экзамене — авторизация или повторный ввод данных с восстановлением их записи.
- Гостевой результат использует оболочку сайта, сайдбар и CTA, с разбором заданий сразу на этой странице.
- Гость получает личную ссылку для просмотра результата и разбора (перерешивание впоследствии исключено решением пользователя).
- Из выбранных гостей формируется отчёт по ссылке для школьного преподавателя: общая таблица, результат ученика, его работа.
- Реализация переиспользует действующие элементы дизайна. Мокап — иллюстрация сценариев, не исходник для переноса в production.

## Итог уточнений

Ответы записаны в DECISIONS.md. Гостю разбор сразу, ученику после утверждения; неявка в конце сеанса без старта; длительность от фактического старта; уведомления только in-app; родитель read-only; Control остаётся в курсе. Вход гостя в SPEC выбран по принципу выдаваемой вручную JOIN-ссылки, без OTP. Свободный PublicExams сохраняется отдельно; домашних тренировок нет.

Дополнительно проверен `inc/Services/Application/JoinCodeService.php`: генерация криптографического кода, хранение хеша через PiiCryptoService, проверка срока при запросе. Его сроки заявки 72 часа/20 дней и форма завершения зачисления не подходят для экзамена напрямую; переиспользовать подход/утилиты, не сам домен заявки.

Проверен `KegeScaleConfig`: максимум 29 первичных; №26/27 по 2; 18→72, 22→83. Ранние демонстрационные пары баллов исправлены.

## Технические требования, не зависящие от ответов

- Самостоятельные проведение, сеанс, участие и попытка. История отмен не удаляется; active booking не смешивается с результатом официальной попытки.
- Вместимость и уникальность активной записи обеспечиваются БД/транзакцией, не проверкой на клиенте и не transient-lock. Повторный запрос возвращает прежний результат.
- Операции старт/неявка/отмена сериализуются по участию. Нельзя одновременно создать попытку и аннулировать её допуск как неявку.
- Смена сеанса проверяет оба места атомарно. Изменение вместимости не может сделать confirmed_count > capacity.
- Гостевой ключ, ключ школьного отчёта и приглашение имеют разные полномочия. Все чтения и действия проверяют область доступа на сервере.
- Фиксировать состав отчёта по конкретным участникам, а не динамическому совпадению школы. Доступ к самой работе проверять по тому же отчёту, а не по произвольному attempt_id.
- До разрешённой публикации ответы/решения не отправляются в HTML/JSON/файлах вообще. CSS-hidden не является защитой.
- Неизменяемость результата должна охватывать состав, условия, ответы, критерии и шкалу. Сейчас ответы хранятся, но это не полноценный снимок контента банка. Для новых проведений SPEC v1 выбирает фиксацию небольшого конфига и блокировку всей цепочки ссылок на контент. Полный снимок банка отложен; одной блокировки списка задач недостаточно.
- Нужны серверные время и часовой пояс проекта, тестируемые через существующий ClockInterface.
- Уведомления только in-app; внешних отправок нет. Создание уведомления не подменяет фиксацию доменного события внутри транзакции бронирования. Событие должно быть надёжно сохранено вместе с изменением; отправка после commit, с повтором ошибок и дедупликацией.
- Для внешних ссылок: криптографический токен, хранение хеша, срок/отзыв согласно решению, noindex/no-store, отсутствие утечки токена в стороннюю аналитику/Referrer. Не использовать nonce как идентификатор гостя.
- Для миграций руководствоваться `.agents/skills/db-migrations/SKILL.md`; отличать дев-сброс схемы от переноса пользовательских данных. Не удалять исторические попытки ради отделения экзамена от урока.
- Старые ссылки и результаты должны получить совместимый путь чтения. Старую роль Control и ограничения доступа курса нельзя менять случайно.

## Проверки будущей реализации

Есть готовые тесты AttemptService, AttemptRevealPolicy, PublicExams, NotificationService, NotificationCronService и JS календарной модели — расширить их, где проверяется та же ответственность.

Файлы `tests/Integration/Repositories/AssessmentAttemptRepositoryTest.php` и `NotificationRepositoryIntegrationTest.php` используют FakeWpdb. Они проверяют форму SQL/репозиторий, но НЕ доказывают отсутствие гонок. Для последнего места, двойной записи и конкурентного старта/неявки нужны отдельные проверки с реальной MariaDB и двумя соединениями/процессами.

Визуальная приёмка: сравнить соседние действующие экраны в одном браузере/масштабе; проверить мобильный календарь, формы, полную работу с табличными ответами, файлы и ручные критерии ОГЭ. Сравнение только с PNG мокапов недостаточно.

## Границы текущей работы

Изучение выполнено без изменения кода LMS и без чтения персональных данных из БД. Статистика 50+ участников — требование пользователя, а не измерение текущих данных. В рабочем дереве уже изменён `.docs/Tasks.md`; этот файл не редактировался в рамках анализа.

## Последние правки макетов

- Только очные сеансы, без онлайн-формата.
- Форма записи остаётся обсуждаемым черновиком, не окончательным UI-заданием.
- «Проведение экзамена» — первый пункт «Мои экзамены» преподавателя.
- В школьном отчёте работа раскрывается под таблицей на той же странице: навигация по заданиям, затем задания.
- Карточки показателей в отчёте и статистике выровнены по размерам.
- Плеер-схема удалён; используется существующая станция.
