# Этап 13. Эксплуатация и приёмка

Зависимости: все предыдущие этапы. Результат: фича принята под нагрузкой, вариант защищён от изменений, данные гостей удаляются по сроку,
экраны сверены визуально, сценарии пройдены людьми, документация и инструкции готовы.

Перед началом прочитать `README.md`. SPEC: §9 (хранение), §12, §16 критерии 25, 32–37, §17, §18 критерий 57. Сценарии: `../E2E-REVIEW.md`.

**Порядок:** 13.2 → 13.3 → 13.5 → 13.1 → 13.4 → 13.6 → 13.7. Код (13.2, 13.3) — раньше приёмок.

## Общие правила этапа

- Результаты проверок — **с числами**, в `.docs/public-exam-feature/ACCEPTANCE.md` (создаётся в 13.1). Формулировки «работает», «проверено» без чисел не принимаются.
- Не прошедшая проверка записывается как не прошедшая, с выводом команды. Исправление — отдельной задачей, затем повторный прогон всего сценария.
- Мок или FakeWpdb не выдаётся за проверку гонки.
- Блокирующие дефекты выпуска: потеря ответа, лишняя оплата, раскрытие чужой работы, сверхбронь, старт таймера без действия участника.

## 13.2 Неизменяемость варианта

**Зачем.** После первого старта состав, веса, длительность и шкала варианта не должны меняться никаким путём: админка, правка в модалке,
импорт, удаление файлов, удаление предмета. Блокировки одного поста работы недостаточно (SPEC §12, критерий 25).

**Проверить перед началом**
- Снимок в проведении (`variant_snapshot`, 2.4.8): состав, номера, баллы, длительность, шкала. Баллы и шкала истории считаются по снимку (7.3.1).
- Все пути изменения работы и её заданий — составить список и записать его в `ACCEPTANCE.md`:
  | Путь | Где искать |
  |---|---|
  | сохранение работы в админке, состав и раскладка | `AssessmentMetaBoxController::handleAssessmentSave()`, `AssessmentManager::setItemIds()`, `AssessmentAuthorCallbacks` (`SaveAssessmentItems`) |
  | правка задания в админке и в модалке | `MetaBoxManager::saveFields()`, `task-editor.js` → `AjaxHook::GetTaskEditorForm` и сохранение; `inc/Callbacks/Task` |
  | смена статуса, корзина, удаление поста | хуки `wp_trash_post`, `before_delete_post`; `inc/Services/Course/ContentDeletionPolicy.php`, `ContentLifecycleService.php` |
  | составные задания (связки, дочерние) | сервис связок (`grep -rn "childrenSummary" inc`) |
  | файлы условия и материалы | `MediaManager`, удаление вложений (`delete_attachment`) |
  | импорт и перенос предмета пакетом | `inc/Services/Subject/Bundle/`, `inc/Services/Import/`, перенос легаси-заданий |
  | удаление и архивация предмета | `inc/Services/Deletion/`, `SubjectCrudCallbacks` |
  | термы номера задания | `TaskNumberTermGuard` (уже защищает номера) |
- Существующие гарды удаления контента — образец способа отказа и текста (`grep -rn "DeleteBlocked\|ContentDeletionPolicy" inc | head`).

  с явной пометкой в отчёте, что шлюз не проверен.
