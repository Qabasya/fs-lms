Нужно добавить новый тип заданий для опросов: Заполнение пропусков

Это в каком-то роде как пропуски в тексте, только вместо ввода текста у нас используется перетаскивание карточек (drag and Drop возьми из КТП, там уже есть интерфейс перетаскивания)

Применяется чаще всего к формулам. И нужно добавить опцию, что порядок неважен

Например, в задании нужно перетащить буквы в формуле веса изображения: V = h*w*i

Причем тут можно любую комбинацию значений: h*w*i, i*w*h, w*h*i и так далее

В этом типе мы отдельно показываем условие задания (по типу "Составьте формулу веса изображения:", отдельно формулу (чуть крупнее шрифт и в таком же стиле карточки с фоном и тенями ( как плитки в КТП), (там будет V =  [ ] * [ ] * [ ]) и в [ ] есть пустые места для плиток с буквами (вариантов может быть больше чем 3, просто отмечаем верные, порядок не важен


И заодно давай поправим "Пропуски в тексте": либо пропуски вписываются вручную в поле для ввода под текстом, либо такие же плитки перетаскиваются в текст (при "вкладывании" в текст шрифт уменьшается до размера шрифта текста и сама плитка пропадает, остаётся только текст и место под плитку которое там было изначально - подчеркивание снизу)

# План реализации (TDD)

Решения: тип — только для работ «Опрос» (`WorkType::Survey`, экзаменов не касается); условие — существующее `task_condition`;
порядок неважен — через **группы взаимозаменяемых слотов**; оценка «всё или ничего»; название нового типа — «Перетаскивание пропусков»;
оптимизация под мобильные (тап плитки → тап слота).

Правило каждого шага: **красный тест → минимальный код → зелёный → рефакторинг**. Не править код во время прогона проверок.
Готово — только после: PHPUnit в контейнере, `npm run test:js`, PHPStan ур. 5 по файлам фичи, `npx eslint .`, `npx stylelint "src/scss/**/*.scss"`, `npx gulp build`.

## Формат данных

**`TaskTemplate::DragFill = 'drag_fill_task'`**, поле `task_drag_fill`:

```
{
  "formula": "V = {1} * {2} * {3}",       // слоты — {N}, нумерация с 1, подряд
  "tiles":   ["h", "w", "i", "k", "d"],   // все плитки, включая лишние; порядок — авторский
  "slots":   [                              // по одному на слот формулы, по индексу
    { "answer": "h", "group": 1 },          // верная плитка + группа
    { "answer": "w", "group": 1 },
    { "answer": "i", "group": 1 }
  ]
}
```

- Условие («Составьте формулу…») — `task_condition` (`ConditionField`), как у остальных шаблонов.
- **Группа** — число. Слоты с одинаковой группой взаимозаменяемы: ответ верен, если мультимножество плиток в слотах группы
  равно мультимножеству верных ответов группы. Группы между собой не смешиваются. Автор, не задавший группы, получает
  каждому слоту свою группу (порядок важен); кнопка «Порядок неважен» ставит всем слотам одну группу (образец `V = h*w*i`).
  `a + b * c`: слот 1 — группа 1, слоты 2–3 — группа 2.
- Повторы (`h*h*i`) считаются мультимножеством, не множеством. Одна плитка из банка — одно использование, если автор
  не добавил её в `tiles` дважды.
- Сравнение плиток — как у `FillChecker`/`AnswerNormalizer` (регистр, пробелы).
- Ответ ученика: `array<int,string>` (индекс слота → плитка), пустой слот — `''`.

**Режим плиток «Пропусков в тексте»**: в `task_gap_text` добавляется `answer_mode` (`input` | `tiles`, отсутствие ключа = `input`,
миграции не нужно) и `extra_tiles` (лишние слова, `string[]`). Плитки банка — первые варианты каждого `[[…]]` + `extra_tiles`.
Ответ ученика и `FillChecker` не меняются (`gapIndex => строка`).

## Решение: «опросные» шаблоны — только в работах типа «Опрос»

Пять шаблонов — Выбор варианта (`Choice`), Сопоставление (`Matching`), Сортировка (`Ordering`), Пропуски в тексте (`Fill`) и новый
«Перетаскивание пропусков» (`DragFill`) — разрешены **только** в работах `WorkType::Survey` (мета `fs_lms_work_type = survey`).
В «Практике», «Самостоятельной» и «Домашней» их быть не должно. Сегодня `allowedTemplates()` у этих типов возвращает `null`
(без ограничений), поэтому запрет вводится как инверсия: у «Опроса» — белый список, у остальных — «все шаблоны, кроме опросных».
