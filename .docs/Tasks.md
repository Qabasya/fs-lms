## Задача 3 — пустые строки и мусорные символы в условиях заданий

### Что есть сейчас

- Плеер курса собирает условие в `StepContentRenderer::conditionHtml()`:
  `SafeHtml::post()` → `wpautop()`. Обрезается только «полностью пустое» условие
  (`'' === trim( $html )`). Хвостовые `<p>&nbsp;</p>`, `<br>`, пустые абзацы, NBSP,
  `​`/`﻿` проходят в разметку как есть.
- Тренажёр и страница задания идут через `TaskMetaService::getCombinedCondition()` →
  `the_content` — другой конвейер, та же проблема.
- `TaskPreviewService` (контрольные) склеивает общее условие и условие через `<br>`.
- При сохранении (`ConditionField::sanitize()`, `EditorField::sanitize()`) содержимое
  только санитизируется, не нормализуется. Импорт легаси (`LegacyTaskRowDTO`) делает
  лишь `trim()` по строке — хвостовые `<p>&nbsp;</p>` из старой базы остаются.

Вероятный источник — импортированные задания и вставка из Word/Google Docs (NBSP, пустые
абзацы, `<br>` в конце, `\r\n`).

### План

1. **Разведка по данным** (docker должен быть запущен): выборка из `wp_postmeta`
   (`meta_key = fs_lms_meta`) заданий, где поля `*_condition` заканчиваются на
   `<p>&nbsp;</p>`, `<p></p>`, `<br>`, `&nbsp;`, `\r\n`, либо содержат `\xE2\x80\x8B`
   (ZWSP), `\xEF\xBB\xBF` (BOM), `\xC2\xA0` в пустых абзацах. Зафиксировать 3–5 примеров
   ID из курса, где пустые строки видны, — на них проверять результат.
2. **Нормализатор** — сервис `Services/Task/ConditionHtmlNormalizer` (DI, не статика —
   список статических утилит закрыт). Метод `normalize( string $html ): string`:
   - убрать `﻿`, `​`–`‍`, `⁠`, управляющие символы (кроме `\n`, `\t`);
     `\r\n` → `\n`;
   - срезать **с начала и с конца** пустые блоки: `<p>` / `<div>` / `<span>`, содержащие
     только пробелы, `&nbsp;`, `\xA0`, `<br>`; хвостовые и ведущие `<br>`; повторять,
     пока срезается (вложенные пустышки);
   - схлопнуть 3+ подряд идущих пустых абзаца **внутри** текста в один (не в ноль —
     автор мог ставить отбивку намеренно);
   - не трогать содержимое `<pre>`, `<code>`, `[latexpage]`/формул — вырезать их в
     плейсхолдеры до чистки и вернуть после (в коде пустые строки значимы).
3. **Точки применения на выводе** (чинит старые данные без миграции):
   - `StepContentRenderer::conditionHtml()` — плеер курса, работы;
   - `TaskMetaService::getCombinedCondition()` и `wrapCommon()` — тренажёр, страница задания;
   - `TaskPreviewService` — контрольные; заодно убрать склейку через `<br>`
     (общее условие уже оборачивается `wrapCommon()`).
4. **Точка применения на сохранении**: `ConditionField::sanitize()` (до
   `LatexPageShortcodeService::ensure()`), `LegacyTaskRowDTO` при импорте. Новые задания
   больше не накапливают мусор.
5. **Разовая чистка базы** — подкоманда WP-CLI в `inc/Cli/` (по образцу
   `TaskFileSchemeCommand`): `wp fs-lms task normalize-conditions [--dry-run]` — проходит по
   всем `{key}_tasks`, нормализует поля `*_condition` в `fs_lms_meta` через
   `MetaBoxManager`/`PostManager`, печатает число изменённых заданий. Прогнать на копии
   базы с `--dry-run`, потом боевой.
6. **Страховка в CSS**: в `.wpc` плеера и `fs-task-condition` — `> :last-child { margin-bottom: 0 }`
   и `p:empty { display: none }` (на случай, если пустышку вставит сторонний фильтр
   `the_content`).
7. Проверить заодно поля, выводимые рядом с условием: подсказка (`hint_html`), тексты
   вариантов ответа, пары, пропуски `Fill` — прогнать через тот же нормализатор там, где
   это HTML; для plain-text значений хватает `trim()` + удаления ZWSP/BOM.

### Проверка
Задания из п. 1 — в тренажёре, в task-шаге, в работе и в контрольной без хвостовых
отступов; задания с кодом в `<pre>` не потеряли пустые строки внутри кода.

## Задача 1 — шаг «Трансляция»: два состояния, запись, ручная ссылка преподавателя

### Что есть сейчас
- `step-broadcast.php`: запись есть (`recording_url` занятия через фильтр
  `fs_lms_recording_url`) → `native` (видео-хром) или `embed` (oEmbed любой http-ссылки);
  записи нет → плашка `.broadcast-placeholder` с фоном, иконкой и кнопкой
  «Перейти к трансляции» (`stream_url` из payload шага).
- Состояние «до/во время/после урока» не учитывается — только наличие записи.
- В `group_lessons` одно поле `recording_url`: либо `s3://bucket/key` (авто-матч
  VideoLibrary или ручная привязка), либо `https://…` (ручная правка из попапа камеры КТП,
  `AjaxHook::SetRecordingUrl`).
- Presign — локальная подпись: «s3 сломалось» (объекта нет, бакет недоступен) сервер не
  видит, это видно только по ошибке `<video>` в браузере.

### Решение по данным
Чтобы фолбэк был возможен, ссылка на внешнюю запись хранится **отдельно** от
s3-указателя: новая колонка `group_lessons.recording_link varchar(1000) NULL`
(внешняя запись — облако, диск). `recording_url` остаётся за s3/авто-матчем.
Миграция — по скиллу `db-migrations` (DDL в `Migration_1_0_0` + догоняющая миграция для
живых установок). `GroupLessonDTO` / `GroupLessonInputDTO` / `GroupLessonRepository` —
поле `recordingLink`, метод `setRecordingLink()`.

> Если не хочется колонку: альтернатива — класть внешнюю ссылку в `recording_url`, когда
> там нет `s3://`. Тогда фолбэк «s3 сломалось» невозможен. Рекомендую колонку.

Существующие https-значения в `recording_url` (ручные правки из КТП) — data-миграцией
перенести в `recording_link`, в `recording_url` оставить только `s3://…`.

### Состояния шага (сервер)
В `LessonPlayerService::renderData()` для `broadcast` передавать в рендер занятие целиком;
`StepContentRenderer::renderBroadcastData()` возвращает:

```
phase:         'live' | 'after'
stream_url:    ссылка на эфир (payload шага)
video_url:     presigned https из s3 (только если фильтр модуля отработал)
record_link:   внешняя ссылка на запись (recording_link)
```

`phase = 'after'`, если занятие `held`, или `ends_at` в прошлом (нет `ends_at` —
`scheduled_at` + длительность слота), или есть любая запись. Иначе `live`.
Preview курса (нет занятия) — всегда `live` без ссылок.

### Разметка (`step-broadcast.php`)
- Убрать `.broadcast-placeholder` (фон, иконку-кружок) и oEmbed-ветку.
- `live`: одна кнопка `b b-pri b-lg` «Подключиться к трансляции» (`stream_url`, новая
  вкладка). Без `stream_url` — строка «Ссылка на трансляцию появится перед началом занятия».
- `after`:
  - есть `video_url` → `video-chrome.php` (как сейчас), под плеером — скрытая
    (`hidden`) кнопка-фолбэк «Открыть запись трансляции» на `record_link`;
  - нет `video_url`, есть `record_link` → кнопка «Открыть запись трансляции»
    (не встраивать);
  - нет ничего → «Запись занятия появится позже».
- `step-video.js`: на `error` у `<video>` шага трансляции — показать фолбэк-кнопку
  (снять `hidden`), а если `record_link` нет — сообщение «Запись временно недоступна».
- SCSS `_step-broadcast.scss`: вычистить стили плашки, оставить отступы кнопки/строки.

### Ручная ссылка в режиме преподавателя
Преподаватель открывает урок своей группы (teacher-режим, `data-teacher="1"`) — в шаге
трансляции под контентом блок «Запись занятия»: поле ссылки + «Сохранить» / «Убрать».
- Рендер только при `$is_teacher` (в preview и у ученика — нет).
- AJAX: существующий `AjaxHook::SetRecordingUrl` перенацелить на `recording_link`
  (он и так «ручная правка ссылки», проверки `authorize( Nonce::SaveSchedule,
  ManageLmsTeaching )` + `requireProgramRow()` уже учитывают «свою группу»). Попап камеры
  в КТП тоже пишет в `recording_link` — одна ручная ссылка на занятие в обоих местах.
- Nonce и имя экшена — в `fs_lms_player_vars` (`BundleLoader`, только для teacher-режима).
- JS — новый модуль `src/js/player/step-broadcast.js` (`initStepBroadcast()` в
  `player.js`), запрос через `playerPost()` из `request.js`; после сохранения шаг
  перерисовывается в состояние `after` без перезагрузки (или `location.reload()` —
  проще и достаточно).
- Валидация: только `http(s)://`, `esc_url_raw` на сервере; `s3://` руками больше не
  принимаем (s3 привязывает VideoLibrary).
- `do_action( 'fs_lms_recording_attached' )` оставить — `RecordingAlertService` снимает
  алерт «проведено без записи»; в `GroupLessonRepository` условие «без записи» =
  пустые **оба** поля.

### Проверка
Занятие в будущем → кнопка эфира; `held` без записей → «появится позже»; вставка ссылки
преподавателем → у ученика кнопка «Открыть запись»; s3-запись → плеер; s3 с битым ключом →
плеер падает в фолбэк-кнопку; модуль VideoLibrary выключен → ссылка из `recording_link`.

### 4.2. Завершение инлайн-шагов без «Далее»
