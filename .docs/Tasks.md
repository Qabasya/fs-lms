1. У меня в разделе "Работы" некорректно отображаются выполненные задачи в wcard-marks. В одной работе у ученика 1 выполнена и 2 нет, стоит 1 галка и 2 крестика. Во второй работе 3 выполнено, но стоят 3 крестика. Определи ошибку и исправь

   **Анализ (найдено, не исправлено).** Причина — `SubmissionService::submitBatch()` (ветка `else` при первой сдаче): per-task строки создаются через `SubmissionInputDTO`, у которого нет `score`/`maxScore`, поэтому в БД остаются `NULL` при `status = graded`. `WorkMarksService::fromSubmission()` для `graded`-строки считает вердикт по `($row->score ?? 0.0) >= ($row->maxScore ?? 1.0)` → `0 >= 1` → «крестик» у всех автопроверенных заданий первой сдачи. Ветка `update` (пересдача) пишет `score/max_score` — поэтому там значки верные, а в первой сдаче «3 из 3 решено» рисуется тремя крестиками.
   **План:**
   1. `SubmissionInputDTO` + `toArray()`: добавить необязательные `score`/`maxScore` (`?float = null`), `SubmissionService::submitBatch()` передаёт в них `$taskResult['score']`/`['maxScore']` при `create`.
   2. `WorkMarksService::fromSubmission()`: для `graded`-строки без `score` (старые данные) не выводить «крестик», а брать вердикт из снапшота агрегата (`$snapshot[$taskId]['verdict']`); сравнение по баллам — только когда `score !== null`.
   3. Data-миграция (скилл `db-migrations`): у `graded` per-task строк с `score IS NULL` проставить `score`/`max_score` из JSON-снапшота агрегатной строки (`answer_text` где `task_id IS NULL`), вердикт `correct` → `weight/weight`, иначе `0/weight`.
   4. Тест: юнит на `WorkMarksService` (первая сдача 3/3 → `[correct×3]`; смесь; ручное `pending`; учительская правка балла поверх снапшота).
